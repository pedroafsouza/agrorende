# T12 · Offline chaos suite

Status: DONE
Wave: W5 · Agent finished: 2026-10-09 02:10

T12 built the offline chaos suite of ARCHITECTURE §15. The suite runs the real mobile sync engine (outbox, push, pull, apply, the media queue and the location buffer) against the real `@agrorende/core` handlers, in one process, through msw. It uses the `agrorende_t12` database and the `.data/media-t12` media folder.

Faults are injected per route and per attempt: dropped responses, 500s, 429s, hangs, captive-portal HTML, slow links and expired S3 URLs. A fake clock and fake file stores let the suite simulate days offline, low disk and multi-gigabyte media without real waiting or real files.

Every scenario and error case listed below is green, with no `it.fails`, no skips and no quarantines. Bugs found in the mobile client were fixed in `apps/mobile/src/**`, which T12 is allowed to do. Server-side gaps are written up as change requests. No git commits were made.

## Done

### Harness (`apps/mobile/test/sync/chaos/`)

- **`harness.ts`** starts the in-process server. It:
  - seeds the database through `createNamedSeededDb`;
  - routes every `/api/v1/**` and S3-style media request to the real core handlers through msw;
  - keeps a request log with route key, device and status;
  - injects faults by route, attempt number and `skip` count (drop the response after the server applied it, 500, 429 with `Retry-After`, hang, HTML portal, slow link, S3 `403 Request has expired`).
- **`device.ts`** models one phone:
  - per-user `node:sqlite` database, the real engine runtime, auth store, media queue and location hook;
  - `kill()` and `restart()`, which abandon in-flight work exactly like a process death;
  - a fake clock and connectivity flags.
- **`files.ts`** is the fake `FileStore`, with free-space control and byte-level corruption.
- **`scenario.ts`, `office.ts`, `catalog.ts`, `suite.ts`** hold the scenario builders, the office-side actions (cancel, reassign, suspend), the EC catalogue lookups and `useChaosSuite()`. `useChaosSuite()` starts one server per file and resets faults and devices after each test.
- **`vitest.config.ts`** runs the suite in Node with `MONGODB_DB=agrorende_t12`, `MEDIA_ROOT=.data/media-t12` and a default `REDIS_URL`. Files run serially.

### Error cases (`apps/mobile/test/sync/chaos/errors.test.ts`, 34 tests)

### Idempotency and corruption (`apps/mobile/test/sync/chaos/idempotency.test.ts`, 5 tests)

- **A7, kill mid-sync.** Rows left IN_FLIGHT by a killed sync loop return to PENDING without a `pushAttemptId`.
- **A7, hang then kill.** A loop killed while the push hangs leaves no IN_FLIGHT row and causes no duplicate.
- **A1.** A mutation id reused by another user, or with another payload, is `VALIDATION_FAILED.mutationIdReuse`. Nothing is applied and nothing is disclosed.
- **EC-SYN-12.** A failing migration keeps the copy-before-migrate backup, drops no table and exports the pending work.
- **EC-SYN-13.** A corrupted copy of the database raises `LOCAL_DB_REPAIR_REQUIRED`, and the original stays intact.

### Round 4 (`apps/mobile/test/sync/chaos/round4.test.ts`, 6 tests: TEN-03, PLT-09, BR-F2-4)

- **C17, role change while offline.** Captured work is never rejected for role reasons, and it drains after the change.
- **EC-PLT-40 inside the 7-day grace.** Field work is still accepted.
- **EC-PLT-40 after the grace.** The server answers RETRY with a 1 h delay. The outbox is kept, retried once an hour (not sooner) and flushed with no duplicates when the organisation is reactivated.
- **A5, scope shrink with a pending outbox.** The job is reassigned to another operator: dirty rows survive, clean out-of-scope rows go, and the pending report is still pushed.
- **A6, rental atomicity.** A failure after the checkout writes, and another after the check-in writes, leaves the rental, inspection, signatures and asset untouched.
- **EC-PLT-42.** The pending-data sheet gates account deletion until the queue is empty. The account is then deleted through `DELETE /api/v1/auth/me`.

### Endurance (`apps/mobile/test/sync/chaos/endurance.test.ts`, T12.12)

The test simulates 7 days on duty offline: 50 400 fixes at 12 s spacing, plus 7 reports with photos and a 20 MB day-0 video. It asserts:

- `DEVICE_UNSYNCED_STALE` is raised while offline.
- After reconnecting, with the video cut mid-upload:
  - the buffer is capped at 50 000 and the most recent 48 h are kept;
  - `LOCATION_BUFFER_TRIMMED` and `MEDIA_PENDING_STALE` are raised.
- A kill and restart raises `UPLOAD_RESUME_AFTER_RESTART` on cold start.
- The final drain:
  - delivers every report and every media file exactly once;
  - sends every remaining fix in batches of 500;
  - leaves the outbox empty and clears the attention codes.

## Assumptions

- **Vitest and `node:sqlite`.** The suite uses Vitest instead of Jest, because `@agrorende/core` pulls ESM-only modules, and it uses `node:sqlite` instead of `better-sqlite3`, because adding a dependency is frozen (R4). The engine talks to both through the same `SqlDb` port, so the behaviour under test is the same.
- **C10** injects the 500 by making the third handler throw, which exercises the real per-mutation transaction rollback.
- **C6** asserts the reauthentication state and the pending count. The banner itself does not show the count yet (T12-002).
- **EC-SYN-10 and EC-SYN-11** fail the whole pull request rather than only page 2. The cursor contract is the same either way.
- **EC-SYN-31** passes `otherDevicesWithPending` to `syncAttention` directly, because the server has no device list endpoint yet (T12-002).
- **EC-SYN-28.** The office-side gap marker on the route history is not emitted. The client-side trim and banner are tested.
- **`MEDIA_LOCKED`.** On a re-upload of a variant that is already stored, it means success. On `media.delete` of a signed attachment, it is a conflict, and the local copy is kept.
- **EC-PLT-42.** The account-deletion gate is UI logic (`pendingItemCount` and `collectPendingWork`), so the suite tests that logic and then calls the real delete endpoint.
- **C17.** A role change bumps `scopeEpoch` and revokes refresh sessions, but the current access token stays valid. The test therefore re-authenticates only when the engine reports `needsReauth`.
- **A6** first sets the seed asset of rental `1201` to operational, because the seed gives it a blocking critical report.
- **Endurance.** The server judges fixes against its own wall clock, so most of the simulated week's fixes are dropped there as out of range. The device's obligation is to deliver every batch once with a 200, and that is what the test asserts.
- **Handoff format.** "Salvar cópia" produces a JSON document rather than a zip, because zip packaging needs a native module that is not in the frozen dependency set (T12-002).
