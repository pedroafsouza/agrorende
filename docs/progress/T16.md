- OPS-06 (T16.1): every ARCHITECTURE §6.4 metric is served by `getAnalytics` in `packages/core/src/modules/ops/analytics.ts` and exposed as `GET /api/v1/ops/analytics` (`apps/web/src/app/api/v1/ops/analytics/route.ts`). The metrics are `mttr`, `first_time_fix`, `reports_by_category`, `wos_by_field_user`, `downtime`, `top_failing`, `rental_utilization`, `rental_revenue` and `cost`.
  - **Filters.** Every metric accepts `from` and `to`, given either as calendar dates in the organisation timezone (`to` inclusive) or as ISO instants, plus `seasonId`. When only a season is given, its start and end dates become the range. An unknown or foreign season answers `NOT_FOUND`, and an inverted range or unknown metric answers `VALIDATION_FAILED`.
  - **Response shape.** Each response carries `series` points (`key`, `label`, `value`, optional `secondary`), a whole-range `summary`, the resolved range and the season. The `cost` metric delegates to the T09 cost roll-up and also returns the full roll-up.
  - Weeks are keyed by their Monday in the organisation timezone.

  - **Overview tab.** Each metric has a Recharts card with its own loading, empty, error-with-retry and ready states.
  - **Cost dashboard tab.** The roll-up can be grouped by asset, site (farm) or season, with totals and a table that mirrors the chart.
  - **Controls.** The range and season filters live in the URL. The tabs are keyboard-operable (arrow keys).
  - **Translations.** All strings are in `messages/{en,pt-BR}/analytics.json`.
- OPS-08 (T16.3): `search` in `packages/core/src/modules/ops/search.ts` serves `GET /api/v1/search?q=` (new `apps/web/src/app/api/v1/search/route.ts`).
  - **Search behaviour.** It searches assets, work orders, field reports, rentals, customers and sites at once, returns at most 5 hits per type, needs at least 2 characters (80 at most) and escapes regex input. It only ever reads the caller's organisation.
  - **Palette.** The command palette in `apps/web/src/features/command-palette/**` is a cmdk dialog. It opens with Ctrl+K or ⌘K, or from `openCommandPalette()`, and is mounted in the admin layout.
  - **Results and actions.** It groups results by type, offers quick actions (new work order, new field report, new rental, new asset) and lists every navigation destination the role can reach. It is fully keyboard-driven, with arrows, Enter and Esc, and handles empty, loading and error states, including a retry.

  - **Boundary layer.** It is a new layer key in the layer filter, fed by the new `GET /api/v1/ops/boundaries`, which returns `plotBoundaries` in `modules/ops/boundaries.ts` as a GeoJSON `FeatureCollection` with plot name, site and area. It is drawn as a terra-coloured fill and outline (`features/ops/{OpsMap,OpsCenter,filters,api,types}.ts(x)`).
- ERP-01 (T16.5): plot boundaries can be drawn and edited on the site detail page.
  - **Entry point.** Each plot row has a "Draw boundary" or "Edit boundary" button that opens `PlotBoundaryDialog` (`apps/web/src/features/sites/PlotBoundaryDialog.tsx`).
  - **Drawing.** The dialog embeds `BoundaryDrawMap`, which uses terra-draw through a small MapLibre adapter written in `terraDrawMapLibre.ts`. You can draw one polygon, drag corners, add midpoints and delete corners.
  - **Typed alternative.** The drawing stays in two-way sync with a textarea of `lat, lng` corners, so a boundary can also be typed or pasted without a pointer.
  - **Area and saving.** The dialog previews the area with the same projection the server uses (`plotGeometry.ts`). Saving sends `PATCH /plots/:id` with `areaHa`, `centroidLat` and `centroidLng` set to null, so the server recomputes them from the polygon. Remove clears the boundary.
  - **Conflicts.** A version conflict is resolved through the shared conflict actions, which reload the plot with the new `GET /api/v1/plots/:id`.
  - **Site map.** Saved boundaries are drawn on the site map.
  - **Round-trip test.** The GeoJSON round trip is covered in core by `packages/core/src/modules/sites/boundary.test.ts`.

## Assumptions
- `GET /search` returns light hits (`id`, `type`, `title`, `subtitle`, `href`) per type instead of full DTOs. The palette needs nothing more, and full work-order or rental DTOs would make every keystroke heavy. Change request T16-003 aligns the api-client.
- `AnalyticsResponse` carries `from`, `to`, `seasonId`, `summary` and, for `cost`, the full roll-up. The api-client placeholder only had `metric`, `unit` and `series` (T16-003).
- `GET /ops/boundaries` and `GET /plots/:id` are new read routes that ARCHITECTURE §8 does not list. They are org-scoped and covered by the rows proposed in T16-001.
- Downtime and utilisation use the season only to set the date range. Assets do not belong to seasons.
- An unknown or foreign `seasonId` answers `NOT_FOUND` (entity `SEASON`), as `seasons/queries.ts` does, and not `VALIDATION_FAILED`.
- terra-draw 1.37 is installed without its MapLibre adapter package. A dependency change is frozen (R4), so T16 wrote a minimal adapter: one GeoJSON source with fill, line and point layers. It is unit-tested against a fake map and exercised in the browser.
- The shared `DataTable` (T04) has no row selection, so the QR selection lives inside `AssetsListPage` (T16-004).
- The QR sheet is limited to 300 assets (10 pages) per request to bound PDF rendering time. The UI warns before the request is sent.
- The boundary round-trip test uses T04's `createHarness("t16_boundary")`, so its database is `agrorende_t04_t16_boundary`.

## Error cases added
- Proposed EC "Plot boundary is not a valid polygon": the typed corners cannot be parsed, a latitude or longitude is out of range, or there are fewer than three corners. Recovery: an inline field error names the problem, Save refuses to send the request until the corners are fixed, and the drawing map stays usable. Owner: T16.
- Proposed EC "QR label sheet failed or too many assets": more than 300 assets are selected, or the PDF request fails. Recovery: an inline warning appears before the request. On failure an `ErrorAlert` offers a retry and keeps the selection. Owner: T16.
- Proposed EC "Command palette search failed": the search request fails or times out. Recovery: an inline error inside the palette with a retry. Quick actions and navigation stay usable. Owner: T16.
