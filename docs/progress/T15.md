## Assumptions
- When billing fails during a rental close, the whole close is rolled back (EC-RN-33). This avoids a closed rental with no bill.
- Rentals are billed automatically at close. The billing panel on a rental therefore only links to the document and never creates one.
- Billing transitions are:
  - update: only while DRAFT;
  - issue: DRAFT → ISSUED;
  - pay: ISSUED → PAID;
  - cancel: DRAFT or ISSUED → CANCELLED;
  - anything else: INVALID_TRANSITION.
- Extend rules:
  - allowed only from RESERVED or ACTIVE;
  - the new end must be later than the current end;
  - an overlapping booking returns ASSET_DOUBLE_BOOKED.
- An INBOUND (rent-in) rental is validated at reserve, and the eligibility check honours `direction`, so rented-in assets are not offered for outbound rental.
- A `/api/v1/billing-documents/preview` route was added so the office can preview totals before issuing.
- `fuelLogCount` in the costs roll-up is optional, so existing callers keep working.
- Mobile fuel history and consumption are read from the local SQLite mirror. The mobile consumption rule mirrors core `computeConsumption`, so offline numbers match the server.
- The asset cost card is shown only to ADMIN and MANAGER. It is read online and offers a retry when offline, because the roll-up is not mirrored locally.
- Fuel price is entered in reais and stored in cents. The currency comes from the organisation mirror row and defaults to BRL.
- New mobile tests were added under `apps/mobile/test/**`, following the pattern used by the other W6 tasks.
