## Assumptions
- **Invite lookup.** The `GET /auth/invites/:code` response shape is typed loosely as `InviteLookup` (`name`, `email`, `orgName`, `role`, `emailRequired`), because the T02 route is not implemented yet.
- **Account deletion.** `DELETE /auth/me` takes the body `{ confirm: true }`.
- **Device lists.** `GET /devices` and `GET /users/:id/devices` return `{ items }`, and each device carries `userName`, `pendingMutations`, `pendingUploads` and `failedMutations`.
- **TeamUser fields.** A TeamUser may carry `email`, `hourlyCostCents`, `mustChangePassword`, `joinedWithOtherEmail` and `invitedEmail`.
- **Invite links.** The resend-invite and reset-link responses use the same `{ url, code, expiresAt }` shape.
- **Settings version.** `GET /settings` may include `syncVersion`. It is sent back as the optimistic-concurrency version and stripped from the patch body.
- **No QR library.** The share panel shows the code in large type instead of a QR image (T04-007).
- **Routes outside the §3.2 rows.** `app/i/**`, `app/r/**`, `(admin)/account` and `(admin)/office-role-required` are not in the DELIVERY-PLAN §3.2 rows, but ARCHITECTURE §14.1 assigns them to the web shell, so T04 implemented them.
- **Code placement.** Account, authentication and style-guide code lives under `features/shell` so that it stays inside T04-owned paths.
- **Style-guide gate.** The development-only gate for the style guide is placed in `(dev)/style-guide/layout.tsx`, because `(dev)/layout.tsx` is not owned by T04.
