### Harness decisions
- **Locale.** The UI language is pinned with the `NEXT_LOCALE` cookie (`setLocale`). Browser `Accept-Language` alone is not enough, because `page.request` calls fall back to pt-BR.
- **Rate limits.** The login and sign-up rate limits (ARCHITECTURE §11, TEN-01) stay real in the stack. Before each login, `support/limits.ts` deletes the sliding-window keys for that e-mail and for the loopback IP in Redis. Before the sign-up test it deletes the sign-up IP bucket. The limits themselves remain covered by the unit tests in `packages/core`.
- **Data.** Each spec creates its own records with unique names (`unique()`, `randomCpf()`). The env project resets the database once per run. No spec depends on data written by another spec.
- **Hydration races.** On a cold dev compile, a control can render before React hydrates it. Forms and dialog openers that showed this are wrapped in `expect(...).toPass()` retries: Google sign-up, "New site" and "New customer". No test uses fixed sleeps.
- **Pseudo-locale.** en-XA is not a served locale: `SUPPORTED_LOCALES` is pt-BR and en. The en-XA screenshots run the en journey, rewrite every visible text node with `pseudoLocalize` from `@agrorende/i18n/pseudo`, take the screenshot, then restore the original text so React and the later steps keep working.

## Assumptions
- The suite runs with one worker and no retries. Every spec drives the same seeded company, and a flaky test should fail loudly rather than be retried.
- For EC-OPS-05, "Keep mine" re-sends only the fields this user changed, based on the values the edit started from. This keeps the other user's unrelated change. It is the least surprising reading of "keep my edits" and matches the "no data loss" rule of `docs/ERRORS.md`.
- The pseudo-locale screenshots are a DOM approximation, because the app does not serve `en-XA`. They show text expansion and clipping, but not pluralisation or ICU argument order.
- In the EC-PLT-36 body, the role reads as the lower-cased role label ("This manager invite is for o***@…").
