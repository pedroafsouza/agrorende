## Assumptions

- **Catalog versions.** The dependency catalog follows the majors named in ARCHITECTURE §4.2 and resolves each one to the latest stable release inside that major, rather than to the absolute newest release of the ecosystem. Packages whose `latest` dist-tag is a pre-release (for example `react-native-reanimated` and `drizzle-orm`) are pinned to the newest stable version instead.
- **Expo SDK.** The mobile app targets Expo SDK 58, the latest stable SDK, with the Expo modules that have not yet shipped a 58 line kept on their newest 57.x release. No beta or canary version is used.
- **`NOT_IMPLEMENTED` is not an `ErrorCode`.** `docs/ERRORS.md` does not define it, so it was not added to the catalog. The 136 placeholder route handlers in `apps/web` return a locally typed `NOT_IMPLEMENTED` envelope; real failures go through `AppError` and `ERROR_META` in `withApi.ts`. T02 replaces the placeholders with real handlers.
- **Locale registry mirrored in contracts.** `packages/contracts` cannot import `packages/i18n` under the ARCHITECTURE §4 dependency rules, so the supported-locale list exists in both `contracts/src/settings.ts` and `packages/i18n`. `pnpm i18n:check` compares the two, so a divergence fails the gate.
- **`apps/web/messages/*/errors.json` carries the 78 server-facing codes.** The mobile app and `packages/i18n` carry all 188, which includes the client-only codes that the web admin never raises.
- **Environment loading.** ARCHITECTURE §16 does not name a loader, so the root `.env` is loaded by Node's built-in `--env-file-if-exists=../../.env` in each package script and by a small dependency-free loader in `scripts/devloop/env.ts`. Variables already present in the environment always win over the file.
- **Relative `MEDIA_ROOT`.** `.env.example` ships `MEDIA_ROOT=./.data/media`. A relative value is resolved against the repository root (found by walking up to `pnpm-workspace.yaml`), not against the current working directory, so `pnpm storage:init` writes to `<repo>/.data/media` regardless of which package the script runs from. Absolute values are used unchanged.
- **The disabled e2e CI job.** T01 scaffolds the `e2e` job but T11 owns it. `if: ${{ false }}` is rejected by actionlint, so the job is gated on `if: ${{ vars.ENABLE_E2E == 'true' }}`. T11 only has to set the repository variable.
- **`apps/web/AGENTS.md`.** `next dev` writes and re-adds a `nextjs-agent-rules` block into that file. It is committed with the rest of the work so the tree stays clean.
