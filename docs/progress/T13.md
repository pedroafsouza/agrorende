## Done

- **Simulator (`pnpm simulate`)**, in `apps/worker/src/simulate.ts` (root script `pnpm simulate`,
  worker script `simulate`). For every simulated person it does the following:
  - signs in with the seed password, registers a simulated device, and records location consent
    and duty ON;
  - connects to the realtime service and sends a location every 3 seconds, falling back to REST
    `POST /api/v1/locations` when the socket is down;
  - patrols between the organisation's sites when it has no job;
  - walks each job assigned to it from accept through on-the-way, arrived and start work to
    complete, using the real work-order mutations;
  - on SIGINT or SIGTERM, sets every simulated person OFF_DUTY before it exits.

  Options are `--users`, `--speed`, `--duration`, `--base-url`, `--ws-url` and `--help`.

## Assumptions

- `pnpm dev:setup` and `docker compose` were not used, because they would clash with the shared
  fleet containers (Mongo, Redis and the mock OIDC provider) that other agents use. Instead,
  `pnpm db:reset` was run on `agrorende_t13`. The documents still describe `pnpm dev:setup` as the
  normal first run.
- `pnpm devloop --check` fails here only because those shared containers are not services of this
  repository's compose project. On a normal machine they are.
- Ctrl-C was reproduced with `kill -INT` on the simulator's node process, because the agent has no
  terminal. The shutdown path is the same.
- The SUPPORT entries for SUSPENDED organisations follow EC-OPS-29: the web is read-only but CSV
  exports still work, and EC-PLT-40: phones keep pushing for a 7-day grace period.
- The DEMO uses WO-000002 for the live simulator assignment, because the seed's own active
  assignments are unsuitable (see CR T13-002).
- The website and app store parts of TRANSLATING describe the intended process; `apps/site` does
  not exist yet.

## Gaps

- **Simulator imports:** the simulator imports `@agrorende/api-client` and `socket.io-client` by
  relative path, because the worker's `package.json` does not declare them and R4 forbids
  `pnpm add`. CR T13-001 proposes declaring them. Owner: the orchestrator or T01.
- **Seed data:** several seed records do not match ARCHITECTURE §17. Active work orders are
  assigned to office users, and WO-000006 is assigned to organisation B's administrator, a
  cross-tenant reference. AGR-000012 also carries FR-000012 (IN_REVIEW) and WO-000012
  (COMPLETED). The demo works around this. See CR T13-002. Owner: the seed owner.
- **`/ops/live` type:** the API client's `OpsLiveOperator` type does not match the `/ops/live`
  response. The simulator does not depend on it. See CR T13-003. Owner: T02.
- **Live positions survive a reset:** `pnpm db:reset` does not clear the live-location hash in
  Redis. A person's last simulated position can remain on `/ops/live`, marked stale, until they
  report again. It is mentioned in the DEMO troubleshooting table. Suggested owner: whoever owns
  `scripts/db-reset`.
- **Files that do not exist yet:** `docs/RELEASING.md` and the `infra/compose` production files
  are T18's; RUNBOOK links to them.
- **Human-only steps were not run:**
  - real Google, Apple and Expo credentials;
  - the store consoles;
  - restic and Atlas restores;
  - the phone parts of the demo.
