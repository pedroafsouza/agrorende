# T18-003 · Runtime realtime URL for the web client and an app-level production guard

Status: OPEN
Requested by: T18 · Wave: W5
Target: `apps/web/src/features/shell/useRealtime.ts` (owner: T04), `packages/core/src/auth/oidc.ts`
(owner: T02) and `packages/core/src/modules/tenancy/config.ts` (owner: T20)
Kind: other

## Problem

1. **Realtime URL is baked at build time.** `useRealtime.ts` reads
   `process.env.NEXT_PUBLIC_REALTIME_URL`, which `next build` inlines into the client bundle.
   ARCHITECTURE §18.4 requires production to run the exact image digest that ran on staging, and
   staging and production use different realtime hosts (`ws.staging.agrorende.com.br` and
   `ws.agrorende.com.br`), so one build cannot serve both without a rewrite.
2. **No app-level production guard.** ARCHITECTURE §18.1 says production refuses to start when
   `GOOGLE_OIDC_ISSUER` is not `https://accounts.google.com`, Atlas secrets are missing or the
   Apple keys are missing. `oidc.ts` and `tenancy/config.ts` fall back to
   `https://accounts.google.com` when the variable is unset, but accept any issuer (including the
   local mock at `http://localhost:4003/google`) when it is set, and nothing checks the Atlas URI
   or Apple keys at start.

## Proposed change

1. Serve the realtime URL at runtime: render it from the server (for example a
   `<meta name="agrorende-realtime-url">` in the root layout read from `process.env` on the server,
   or a small `GET /api/v1/config` endpoint) and read it in `useRealtime.ts`, keeping
   `NEXT_PUBLIC_REALTIME_URL` as the local default.
2. Add a start-up check in `packages/core` (called by web, realtime and worker when
   `APP_ENV=production`) that throws with a clear message unless
   `GOOGLE_OIDC_ISSUER === "https://accounts.google.com"`,
   `APPLE_OIDC_ISSUER === "https://appleid.apple.com"`, `MONGODB_URI` starts with
   `mongodb+srv://`, and `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY`,
   `AUTH_ENCRYPTION_KEY`, `JWT_SECRET` and `MEDIA_URL_SECRET` are set.

## Workaround in place

1. `apps/web/Dockerfile` builds with the placeholder `NEXT_PUBLIC_REALTIME_URL=__AGRORENDE_REALTIME_URL__`
   and `infra/docker/web-entrypoint.sh` replaces it in `.next` (server and static files) with the
   container's `NEXT_PUBLIC_REALTIME_URL` at start. The value must be an `http(s)` URL without
   quotes or spaces; the last applied value is kept in `.next/.realtime-url`, so restarts with a
   different value work.
2. `infra/scripts/validate-env.sh` enforces the same rules on the rendered `.env` in `deploy.yml`
   before anything reaches a VM, for staging and production.

## Impact if rejected

The image keeps rewriting its own bundle at start (one more moving part, and the files must stay
writable by uid 1000), and a production container started by hand with a wrong issuer is not
stopped by the app itself, only by the deploy workflow.
