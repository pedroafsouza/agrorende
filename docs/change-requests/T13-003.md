# T13-003 · The API client's `OpsLiveOperator` type does not match the `/ops/live` response

Status: OPEN
Requested by: T13 · Wave: W5
Target: packages/api-client/src/types.ts (owner: T02)
Kind: contract

## Problem

`GET /api/v1/ops/live` returns operator objects shaped like this (observed on the seeded
`agrorende_t13` stack while `pnpm simulate` was running):

```
userId, name, lat, lng, accuracyM, heading, speedMps, recordedAt, lastSeenAt,
dutyStatus, state, stale, deviceId, activeWorkOrderId
```

The `OpsLiveOperator` interface in `packages/api-client/src/types.ts` declares `online` and
`workOrderId` instead of `lastSeenAt`/`stale` and `activeWorkOrderId`, has no `heading`,
`speedMps` or `deviceId`, and its `state` union lacks `ON_HOLD`. A client that trusts the type
reads `undefined` for those fields.

## Proposed change

Align the interface with the server response: replace `online` with `stale: boolean` and
`lastSeenAt: string | null`, rename `workOrderId` to `activeWorkOrderId`, add `heading`,
`speedMps` and `deviceId` (all nullable), and add `"ON_HOLD"` to `state`.

## Workaround in place

`apps/worker/src/simulate.ts` does not read `/ops/live`. The verification in
`docs/progress/T13.md` reads the raw JSON with `curl`.

## Impact if rejected

Any future consumer of the typed client sees missing fields without a compile error.
