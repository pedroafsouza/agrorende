# T05-006 · `exports.build` in the core job enqueue seam

Status: OPEN
Requested by: T05 · Wave: W2
Target: `packages/core/src/jobs/index.ts` (owner: T01)
Kind: seam signature

## Problem
`core/jobs` `JOB_NAMES` lists only `events.dispatch`, `media.cleanupPending` and `locations.prune`, and `enqueueJob` throws `notImplemented`. The export API therefore cannot wake the worker when it creates an `ExportJob`.

## Proposed change
- Add `"exports.build"` (and the other names in `apps/worker/src/jobRegistry.ts`) to `JOB_NAMES`.
- Implement `enqueueJob` with a BullMQ `Queue` whose `prefix` is `agrorende` for the default database and `agrorende:<MONGODB_DB>` otherwise, to match `workerQueuePrefix` in `apps/worker/src/jobs/index.ts`.
- Use the queue names from `JOB_REGISTRY`.

Web routes would then pass `enqueue: (jobId) => enqueueJob("exports.build", { jobId })` in `ExportDeps`.

## Workaround in place
The worker registers a 60-second `exports.build.poll` scheduler that builds `QUEUED` jobs. Claiming is atomic, so a job is still built and notified once.

## Impact if rejected
Large exports start up to one minute later.
