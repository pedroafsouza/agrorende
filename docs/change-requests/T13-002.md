# T13-002 · Seed assigns active work orders to office users and to another organization

Status: APPLIED
Requested by: T13 · Wave: W5
Target: packages/db/seed/index.ts (owner: T01, frozen; T10 for fixes)
Kind: other

## Problem

ARCHITECTURE §17 describes field technicians working on the seeded work orders, and the demo
and `pnpm simulate` rely on that. The seed instead picks the assignee with
`pick(userIds, 4 + index)`, which cycles through all ten seeded users, including office users
and the administrator of Organization B. On a fresh `pnpm db:seed --force` in
`agrorende_t13` the active work orders are assigned as follows:

```
WO-000002 OPEN        tecnico2@agrorende.dev  FIELD   sameOrg=true
WO-000003 ASSIGNED    tecnico3@agrorende.dev  FIELD   sameOrg=true
WO-000004 ASSIGNED    locacao@agrorende.dev   FIELD   sameOrg=true
WO-000005 ACCEPTED    convite@agrorende.dev   FIELD   sameOrg=true   (an invited user who never signed in)
WO-000006 EN_ROUTE    admin@boavista.dev      ADMIN   sameOrg=false  (cross-tenant reference)
WO-000007 EN_ROUTE    admin@agrorende.dev     ADMIN   sameOrg=true
WO-000008 ON_SITE     gerente@agrorende.dev   MANAGER sameOrg=true
WO-000009 IN_PROGRESS despacho@agrorende.dev  MANAGER sameOrg=true
WO-000010 IN_PROGRESS inspetor@agrorende.dev  FIELD   sameOrg=true
WO-000011 ON_HOLD     tecnico1@agrorende.dev  FIELD   sameOrg=true
```

The consequences are:

- WO-000006 in Organization A references a user of Organization B. This breaks tenant isolation
  in the data, even though no route currently exposes it.
- Four active work orders belong to office users, who have no phone queue and no live
  position, so the Operations Center shows EN_ROUTE and ON_SITE jobs with no moving operator.
- `pnpm simulate` can only drive WO-000003 (Lucas) and WO-000004 (Rafael). Pedro has no active
  job and patrols instead.

## Additional deviation: AGR-000012

`docs/ARCHITECTURE.md` §17 describes AGR-000012 as the clean tractor for the offline-report demo,
with no open failure report or work order. The seed currently gives it FR-000012 (status
`IN_REVIEW`) and WO-000012 (status `COMPLETED`). The demo still works, because a new report is
created regardless, but the Office sees an extra in-review report on the same machine, which
makes the "new report appears on the map" moment less clear. Proposed fix: skip AGR-000012 when
the seed distributes failure reports and work orders over assets (or pick the assets by index
from a list that excludes it).

## Proposed change

Assign active seeded work orders only to the four field technicians of Organization A, and
keep Carlos at exactly one open work order (the ON_HOLD one), as §17 requires:

```diff
-    assigneeId: index === 0 ? null : pick(userIds, 4 + index),
+    assigneeId:
+      index === 0
+        ? null
+        : index === 10
+          ? userIds[4] // Carlos: exactly one open work order (ON_HOLD, waiting for parts)
+          : pick([userIds[5], userIds[6], userIds[7], userIds[3]], index), // Pedro, Lucas, Rafael, Joana
```

`previousAssigneeIds` already uses `userIds[4]`, which is correct.

## Workaround in place

None is needed in code. `pnpm simulate` drives whatever is assigned to the simulated users.
`docs/DEMO.md` has the dispatcher assign an open work order to Pedro during the demo, so the
full accept → complete loop is visible regardless of this seed.

## Impact if rejected

The seed keeps one cross-tenant reference. The live map shows active jobs without operators,
and the simulator only animates two of the four technicians through work orders.

## Resolution

Applied at the W5 gate. `packages/db/seed/index.ts` now assigns the active seed work orders to Organization A field technicians only: Carlos has exactly one open job (the ON_HOLD one) and the others rotate over Pedro, Lucas, Rafael and Joana. AGR-000012, the clean tractor of the offline-report demo (§17), no longer gets a seeded report or work order, and the seeded `WO_ASSIGNED` notification points at Carlos's job. `buildSeed` is exported so the invariants can be tested without a database. A new `packages/db/test/seed.test.ts` asserts these invariants, and `packages/db/tsconfig.json` includes `test`. `packages/core/src/__tests__/seams.test.ts` (open count per assignee) and `docs/DEMO.md` were updated to the new numbers. `pnpm check` (including the golden path), the chaos suite and the Playwright suite pass on the new seed.
