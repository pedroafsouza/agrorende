# T18-004 · EAS project id in the mobile app config

Status: APPLIED-PARTIAL
Requested by: T18 · Wave: W5
Target: `apps/mobile/app.config.ts` (owner: T01, frozen)
Kind: other

## Problem

`.github/workflows/mobile.yml` runs `eas build:list`, `eas update` and `eas build` in the cloud.
EAS CLI links a project through `extra.eas.projectId` in the Expo config. `app.config.ts` is a
dynamic config without `extra.eas.projectId`, so `eas init` cannot write the id and every EAS
command in CI stops with "EAS project not configured" until the id is present. The update URL is
already read from `EAS_UPDATE_URL`, but the project id is not.

## Proposed change

In the object returned by `app.config.ts`, add the project id from the environment, next to the
existing `updates` entry:

```ts
const easProjectId = process.env.EAS_PROJECT_ID;
// …
extra: {
  ...config.extra,
  ...(easProjectId === undefined ? {} : { eas: { projectId: easProjectId } }),
},
```

and list `EAS_PROJECT_ID` in `.env.example` next to `APP_VARIANT`. `mobile.yml` would then pass
`EAS_PROJECT_ID: ${{ vars.EAS_PROJECT_ID }}` (a non-secret GitHub variable) together with
`EAS_UPDATE_URL`. Alternatively, hard-code the id once the human creates the EAS project
(ARCHITECTURE §18.4 RUNBOOK steps).

## Workaround in place

None that T18 can apply inside its lane: `mobile.yml` passes `EAS_UPDATE_URL` and documents the
EAS project creation as a human step in `docs/RELEASING.md` §2. The workflow passes actionlint and
fails early with a clear message when `EXPO_TOKEN` is missing.

## Impact if rejected

The first `mobile.yml` run fails until someone adds the project id to `app.config.ts` by hand.

## Resolution

Applied at the W5 gate as far as the code allows.

- `apps/mobile/app.config.ts` reads `EAS_PROJECT_ID` through the exported `resolveEasProjectId(env)` and sets `extra.eas.projectId`. The id is optional for local development. During an EAS build (`EAS_BUILD=true`) a missing id throws a message that names the variable, and an id that is not a UUID always throws. It is tested by `apps/mobile/test/engine/appConfig.test.ts`.
- `.env.example` documents `EAS_PROJECT_ID`.
- Both "Require EXPO_TOKEN" steps in `.github/workflows/mobile.yml` now also fail with `::error::` when the `EAS_PROJECT_ID` repository variable is empty.

What a human must do: create the EAS project (`eas init` while logged in to the Expo account), then set the repository variable `EAS_PROJECT_ID` to its UUID (Settings → Secrets and variables → Actions → Variables), alongside the existing `EXPO_TOKEN` secret. No agent can do this, because it needs the Expo account.
