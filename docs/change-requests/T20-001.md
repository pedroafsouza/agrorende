# T20-001 · OAuth "create company" intent hands off to the sign-up ticket

Status: APPLIED
Requested by: T20 · Wave: W3
Target: `apps/web/src/app/api/v1/auth/oauth/**`, `packages/core/src/auth/**` (owner: T02)
Kind: seam wiring

## Problem
TEN-01 starts self-service sign-up from the Google or Apple button on `/signup`. Those buttons link to `/api/v1/auth/oauth/{google,apple}/start?intent=signup`. The T02 OAuth start and callback routes do not know the `signup` intent, so today a new Google or Apple identity without a user ends with `ACCOUNT_NOT_FOUND` instead of reaching the company form. The mobile "Create company" flow also needs the one-time login code that T20 returns after sign-up to be redeemed through `/api/v1/auth/oauth/exchange`.

## Proposed change
1. OAuth start accepts `intent=signup` (and, for the app, `client=app`, `appRedirectUri` and `codeChallenge`) and keeps it in the signed state cookie.
2. On callback with `intent=signup`, after the provider identity is verified, call `issueSignupTicket(identity, { client, appRedirectUri, codeChallenge })` from `@agrorende/core/modules/tenancy/signupTicket` and redirect to `/signup/company?ticket=<ticket>`. If the identity already belongs to a user, sign in as usual instead.
3. `POST /api/v1/auth/oauth/exchange` accepts the T20 sign-up login code: when the code is a sign-up code, call `tenancy.redeemSignupLoginCode(code, codeVerifier, meta)` from `@agrorende/core` (exported through `modules/index.ts`), which enforces single use and returns the user and the session tokens.

## Workaround in place
None for the redirect. T20 implements and tests the ticket (`signupTicket.ts`), the company form (`/signup/company?ticket=`) and `redeemSignupLoginCode` in core; `service.test.ts` exercises the whole flow with a ticket minted directly.

## Impact if rejected
Self-service sign-up cannot be reached from the UI; companies can only be created by seed or by staff.

## Resolution

Deferred to T10. The OAuth routes exist as files, but every one of them (`GET /auth/oauth/:provider/start`, the Google and Apple callbacks, `POST /auth/oauth/exchange` and `POST /auth/apple`) is still mapped to `auth.oauthUnavailableHandler` in `packages/core/src/auth/api/index.ts`. There is no working OAuth flow to carry a `signup` intent, so the hand-off to `issueSignupTicket` and `redeemSignupLoginCode` cannot be wired until Google and Apple sign-in themselves are implemented. T10 should implement the intent together with the provider flows; the ticket, the company form and the redemption are already implemented and tested in core.

## T10 resolution
T10 implemented the OAuth routes in `packages/core/src/auth/oauth.ts` and `packages/core/src/auth/api/oauth.ts`.

`GET /auth/oauth/:provider/start` accepts the `login`, `signup` and `invite` intents. It also accepts the app parameters: `client=app`, `appRedirectUri` (or the mobile `redirect` alias) and `codeChallenge` (or `challenge`). The redirect scheme must belong to `OAUTH_MOBILE_SCHEMES`. All of these values are kept in an encrypted, ten-minute state token, which is bound to an httpOnly cookie.

On the callback, a provider identity with no matching user, no invite and `intent=signup` is passed to `issueSignupTicket` together with the app client options. The browser is then redirected to `/signup/company?ticket=<ticket>`. An identity that already has a user simply signs in.

`POST /auth/oauth/exchange` decodes the code it receives. A sign-up login code (`tokenUse: "signup_login"`) is delegated to `redeemSignupLoginCode(code, verifier, meta)`. Any other code is redeemed as a sixty-second, single-use OAuth login code bound to the app's PKCE challenge. Both paths return the same token body as password login.

The full web and app sign-up paths are covered by `packages/core/src/auth/oauth.test.ts` against the local mock issuer.

One limitation remains in T20's own file: the app redirect pattern in `signupTicket.ts` only allows the `agrorende://` scheme, so sign-up from the development and preview app builds (`agrorende-dev://`, `agrorende-preview://`) is rejected there.
