# T20-001 · OAuth "create company" intent hands off to the sign-up ticket

Status: OPEN
Requested by: T20 · Wave: W3
Target: `apps/web/src/app/api/v1/auth/oauth/**`, `packages/core/src/auth/**` (owner: T02)
Kind: seam wiring

## Problem
TEN-01 starts self-service sign-up from the Google or Apple button on `/signup`. Those buttons link to `/api/v1/auth/oauth/{google,apple}/start?intent=signup`. The T02 OAuth start and callback routes do not know the `signup` intent, so today a new Google or Apple identity without a user ends with `ACCOUNT_NOT_FOUND` instead of reaching the company form. The mobile "Create company" flow also needs the one-time login code that T20 returns after sign-up to be redeemed through `/api/v1/auth/oauth/exchange`.

## Proposed change
1. OAuth start accepts `intent=signup` (and, for the app, `client=app`, `appRedirectUri` and `codeChallenge`) and keeps it in the signed state cookie.
2. On callback with `intent=signup`, after the provider identity is verified, call `issueSignupTicket(identity, { client, appRedirectUri, codeChallenge })` from `@agrorende/core/modules/tenancy/signupTicket` and redirect to `/signup/company?ticket=<ticket>`. If the identity already belongs to a user, sign in as usual instead.
3. `POST /api/v1/auth/oauth/exchange` accepts the T20 sign-up login code: when the code is a sign-up code, call `tenancy.redeemSignupLoginCode(code, codeVerifier, meta)` from `@agrorende/core` (exported through `modules/index.ts`), which enforces single use and returns the user and the session tokens.

## Workaround in place
None for the redirect. T20 implements and tests the ticket (`signupTicket.ts`), the company form (`/signup/company?ticket=`) and `redeemSignupLoginCode` in core; `service.test.ts` exercises the whole flow with a ticket minted directly.

## Impact if rejected
Self-service sign-up cannot be reached from the UI; companies can only be created by seed or by staff.
