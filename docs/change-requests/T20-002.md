# T20-002 · Delegate `assertOrganizationWritable` to the tenancy module and gate office writes

Status: APPLIED
Requested by: T20 · Wave: W3
Target: `packages/core/src/tenancy/index.ts` (owner: T01), `apps/web/src/server/withApi.ts` and the sync push (owners: T01, T02), integration by T10
Kind: seam wiring

## Problem
EC-OPS-29 and EC-PLT-40 require SUSPENDED and CANCELLED organisations to be read-only: office writes fail with `ORG_SUSPENDED`, exports stay available, and the field outbox is held rather than rejected. The T01 seam `assertOrganizationWritable(ctx)` in `packages/core/src/tenancy/index.ts` still throws `notImplemented`, and no route calls it.

## Proposed change
1. Replace the body of `assertOrganizationWritable(ctx)` with `await assertOrgWritable(ctx.orgId)` from `../modules/tenancy/service.js`. T20 implements and tests `assertOrgWritable`.
2. Call it from `withApi` for every non-GET tenant route, except `POST /api/v1/exports*`, `POST /api/v1/auth/*`, `POST /api/v1/org/accept-terms` and the media blob routes, so read-only organisations can still export, sign in and accept terms.
3. In the sync push, use the push gate T02 already reads (`orgPushBackoff`) so suspended field outboxes are held after the 7-day grace and flush on `sync:poke` after reactivation.

## Workaround in place
`assertOrgWritable` exists in `@agrorende/core/modules/tenancy/service` and is covered by `service.test.ts` ("makes SUSPENDED organisations read-only (EC-OPS-29) and reactivation writes sync:poke"). T20's own mutation routes (`/org/cancel`) already enforce the organisation status.

## Impact if rejected
Suspended and cancelled organisations keep full write access, which contradicts TEN-03, TEN-04 and EC-OPS-29.

## Resolution

The orchestrator applied this request at the W3 gate. `assertOrganizationWritable(ctx)` in `packages/core/src/tenancy/index.ts` now delegates to `assertOrgWritable` from `modules/tenancy/service.ts` and is exported through a new `@agrorende/core/tenancy` subpath; `service.test.ts` exercises it in the "makes SUSPENDED organisations read-only" test. `apps/web/src/server/withApi.ts` calls it after the session check for every non-GET, non-HEAD, non-OPTIONS tenant request, except the prefixes listed in `WRITABLE_WHEN_READ_ONLY` (`auth`, `exports`, `org`, `sync`, `media`, `locations`, `devices`, `telemetry`, `notifications/read`, `me`, `assets/qr-sheet`, `platform` and `signup`), so read-only organisations can still sign in, export, accept terms, reactivate, upload pending media and read. The whole `org` prefix is exempt because T20's own `/org/*` routes already enforce the status per action. The predicate `requiresWritableOrg` is covered by `withApi.test.ts`, and the web vitest setup mocks the gate as writable for route tests that run without MongoDB. The sync push needed no change, because `core/src/sync/push.ts` already applies `orgPushBackoff`.
