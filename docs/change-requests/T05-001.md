# T05-001 · Export core modules and let apps type-check against package sources

Status: OPEN
Requested by: T05 · Wave: W2
Target: `packages/core/package.json`, `packages/core/src/index.ts`, `apps/worker/tsconfig.json`, `apps/worker/package.json`, `apps/realtime/package.json` (owner: T01)
Kind: dependency

## Problem
`@agrorende/core` exports only its root entry, so `modules/locations` and `modules/exports` cannot be imported by package name from the realtime gateway, the worker or the web app. ESLint also bans `@agrorende/*/src/*` imports. The worker `tsconfig.json` is frozen with `rootDir: "."`, so a relative import into `packages/*` fails with TS6059. Neither app depends on `@agrorende/db`, so the worker cannot reach `withSyncTx`, `collections` or `setupTestDb` by name.

## Proposed change
- Add subpath exports to `packages/core/package.json`: `"./modules/locations"` and `"./modules/exports"`, each pointing at the module's `index.ts`.
- Add `"@agrorende/db": "workspace:*"` to `apps/worker` and `apps/realtime` (`dependencies`).
- Drop `rootDir` from `apps/worker/tsconfig.json`, or set it to `"../.."` as `apps/realtime` already does.

## Workaround in place
- `apps/realtime/src/core.ts` imports the module sources through a relative path. `apps/realtime/tsconfig.json` already uses `rootDir: "../.."`.
- `apps/worker/src/jobs/index.ts` loads `packages/db/src/index.ts`, `packages/core/src/seams.ts` and the two module `index.ts` files by file URL at runtime, and types them with local structural interfaces.
- `apps/web/src/features/exports/server.ts` imports the module services relatively, as `apps/web/src/lib/core.server.ts` (T04) does.

## Impact if rejected
The URL bridge keeps working under `tsx` and Vitest, but the worker's types are not checked against the real module signatures. A signature change in core would only fail at runtime or in the worker tests.
