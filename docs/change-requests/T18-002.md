# T18-002 · Load worker peer jobs and the Apple revoke handler with static imports

Status: OPEN
Requested by: T18 · Wave: W5
Target: `apps/worker/src/jobs/index.ts` (owner: T05)
Kind: seam signature

## Problem

The worker job registry finds peer job handlers and the Apple revoke handler by file path at
runtime:

- `peerJobFile(name)` looks for `<JOBS_DIR>/<name>.ts` or `.js` next to `index.ts`, where
  `JOBS_DIR` is derived from `import.meta.url`;
- the Apple revoke handler is imported from `path.join(REPO_ROOT, "packages/core/src/auth/apple.ts")`
  with `REPO_ROOT = JOBS_DIR/../../../..`.

A bundled production image has no source tree, so these lookups silently fall back to the
`worker.job.noop` handler (T18 observed this in its first worker image: every peer job logged
`worker.job.noop`), and the Apple lookup only works if the image mirrors the repository layout
and ships a `.ts` file. Both make the image layout part of the worker's behaviour.

## Proposed change

Import the handlers statically so any bundler resolves them at build time:

```ts
import { handler as notificationsPush } from "./notifications.push.js";
// … one import per peer job …
import { appleRevoke } from "@agrorende/core/auth/apple"; // or the documented core entry point
```

and keep the noop fallback only for tests (`vi.mock`) rather than for a missing file. If dynamic
loading must stay, resolve paths with `import.meta.resolve("@agrorende/core/…")` instead of a
relative repository root.

## Workaround in place

`infra/docker/bundle.mjs` (worker mode) builds the worker as one esbuild build with code
splitting, places the entry, every peer job and every shared chunk in
`/app/apps/worker/src/jobs/` (so `JOBS_DIR` finds `<name>.js`), writes `/app/package.json` with
`"type": "module"` and generates `/app/packages/core/src/auth/apple.ts` as a one-line re-export of
the bundled `apple.js` (Node 24 strips the types). The container run in `docs/progress/T18.md`
shows peer jobs loaded and no `worker.job.noop` line.

## Impact if rejected

The worker image keeps depending on the repository-shaped layout produced by `bundle.mjs`; any
change to the registry's path logic can silently turn production jobs into no-ops.
