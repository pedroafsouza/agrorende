# T05-010 · Messages catalogue for CSV export headers

Status: APPLIED
Requested by: T05 · Wave: W2
Target: `packages/i18n/messages/{pt-BR,en}/exports.json` (owner: T01 or T10)
Kind: translation

## Problem
R9 wants every user-facing string to be an ICU key, but T05 owns no messages file. CSV column headers and boolean labels are user facing.

## Proposed change
Add an `exports` namespace with `exports.headers.<column>` and `exports.boolean.{true,false}` for every key in `EXPORT_HEADERS`. Then make `packages/core/src/modules/exports/headers.ts` read the catalogue.

## Workaround in place
`packages/core/src/modules/exports/headers.ts` holds a typed pt-BR and en map. A test checks that every column has both locales.

## Impact if rejected
Header translations live outside the catalogue, so `pnpm i18n:check` does not cover them.

## Resolution
Deferred to T10. Moving the CSV header labels into an `exports` messages namespace adds a T01 catalogue and changes how core reads server-side translations. That is the same change as T02-005 for notification templates, and T10 should make both together so that the server reads messages one way. The typed pt-BR and en map in `packages/core/src/modules/exports/headers.ts` is complete and tested, so nothing is blocked.

## T10 resolution
Applied by T10, together with T02-005, so that the server reads messages one way. A new `exports` namespace (`packages/i18n/locales/pt-BR/exports.json` and `packages/i18n/locales/en/exports.json`) holds `headers.<column>` for every column that was in `EXPORT_HEADERS` and `boolean.true` / `boolean.false`, copied verbatim from the former map. `packages/core/src/modules/exports/headers.ts` keeps its public exports (`EXPORT_HEADERS`, `BOOLEAN_LABELS` and `ExportHeaderKey`) with the same shapes, but builds them from `SERVER_MESSAGES` in `@agrorende/i18n/server`. `ExportHeaderKey` is now derived from the pt-BR catalogue keys, and TypeScript rejects a column that is missing from either locale. `pnpm i18n:check` covers the namespace through the usual pt-BR reference comparison, and `packages/core/src/modules/exports/headers.test.ts` asserts that every column and both boolean labels resolve in pt-BR and en.
