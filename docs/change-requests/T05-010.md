# T05-010 · Messages catalogue for CSV export headers

Status: OPEN
Requested by: T05 · Wave: W2
Target: `packages/i18n/messages/{pt-BR,en}/exports.json` (owner: T01 or T10)
Kind: translation

## Problem
R9 wants every user-facing string to be an ICU key, but T05 owns no messages file. CSV column headers and boolean labels are user facing.

## Proposed change
Add an `exports` namespace with `exports.headers.<column>` and `exports.boolean.{true,false}` for every key in `EXPORT_HEADERS`. Then make `packages/core/src/modules/exports/headers.ts` read the catalogue.

## Workaround in place
`packages/core/src/modules/exports/headers.ts` holds a typed pt-BR and en map. A test checks that every column has both locales.

## Impact if rejected
Header translations live outside the catalogue, so `pnpm i18n:check` does not cover them.
