# T12-001 · Run the offline chaos suite in CI and typecheck its sources

Status: OPEN
Requested by: T12 · Wave: W5
Target: `apps/mobile/package.json`, `apps/mobile/tsconfig.json`, `.github/workflows/ci.yml` (owner: T01 and T18)
Kind: other

## Problem
The chaos suite in `apps/mobile/test/sync/chaos.test.ts` and `apps/mobile/test/sync/chaos/**` runs with Vitest in Node, because it loads the real `@agrorende/core` (ESM-only dependencies such as `jose`) next to the mobile sync engine. It is not part of `pnpm check`: the mobile `test` script runs Jest, whose `testMatch` only covers `test/engine` and `test/ui`. In addition, `apps/mobile/tsconfig.json` does not include the `test/` folder, so `tsc --noEmit` does not typecheck the suite (ESLint does lint it). ARCHITECTURE §15 asks for the suite to run in CI three times in under five minutes.

## Proposed change
1. Add `"test:chaos": "vitest run --config test/sync/chaos/vitest.config.ts"` to `apps/mobile/package.json`, and declare `vitest` as a mobile devDependency (it currently resolves through the workspace hoist).
2. Add a `tsconfig.test.json` in `apps/mobile` that extends the main config and includes `test/sync/**`, and typecheck it in the `typecheck` script.
3. Add a CI job that starts MongoDB and Redis services, sets `MONGODB_DB=agrorende_t12`, `MEDIA_ROOT=.data/media-t12` and `REDIS_URL`, and runs `pnpm --filter mobile test:chaos` three times.

## Workaround in place
The suite is run by hand from `apps/mobile` with `pnpm exec vitest run --config test/sync/chaos/vitest.config.ts`. The Vitest config sets `MONGODB_DB`, `MEDIA_ROOT` and a default `REDIS_URL` of `redis://localhost:6379`.

## Impact if rejected
The chaos suite does not guard regressions in continuous integration, and the release gate depends on a manual run.
