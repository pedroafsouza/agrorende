# T15-002 · Register the fuel mutator in the mobile mutator barrel and drop the old stub

Status: APPLIED
Requested by: T15 · Wave: W6
Target: `apps/mobile/src/sync/mutators/index.ts`, `apps/mobile/src/sync/mutators/fuelLogs.ts` (owner: T03)
Kind: code

## Problem
T15 owns `apps/mobile/src/sync/mutators/fuel.ts` and implemented `createFuelLog` there with `defineMutator` (`fuelLog.create`, entity type `FUEL_LOG`). The side-effect barrel `src/sync/mutators/index.ts` imports every mutator module so that a scope-reset rebase can re-run pending commands locally (CR T06-003), but it does not import `./fuel`. A pending fuel log is still pushed by the outbox without the barrel. However, after a scope reset its optimistic mirror row would not be re-applied until the server copy arrives. A leftover file `src/sync/mutators/fuelLogs.ts` still exports a `createFuelLog` that throws `notImplemented`, which invites the wrong import.

## Proposed change
- Add `import "./fuel";` to `apps/mobile/src/sync/mutators/index.ts` (keep alphabetical order, after `./assets`).
- Delete `apps/mobile/src/sync/mutators/fuelLogs.ts`. Nothing imports it (`grep -rn "mutators/fuelLogs" apps/mobile` is empty).

## Workaround in place
`FuelNewScreen` imports `createFuelLog` directly from `src/sync/mutators/fuel.ts`, so saving, the outbox push and the exactly-once guarantee work today (`apps/mobile/test/engine/fuel.test.ts`).

## Impact if rejected
After a rare scope reset, an unsynced fuel log disappears from the machine profile until the next pull brings the server copy back. The stub file stays as dead code.

## Resolution

Applied by the W6 gate. The mobile mutator barrel `apps/mobile/src/sync/mutators/index.ts` imports `./fuel` and `./comments`, and the dead `fuelLogs.ts` stub is deleted. `apps/mobile/test/ui/moreScreen.test.tsx` asserts that `fuelLog.create` is registered.
