# T17-002 · Register the comments mutator in the mutator barrel

Status: APPLIED
Requested by: T17 · Wave: W6
Target: `apps/mobile/src/sync/mutators/index.ts` (owner: T03)
Kind: other

## Problem
T17 added `apps/mobile/src/sync/mutators/comments.ts`, which defines the `comment.create` mutator (optimistic insert into the local `comments` mirror plus the outbox row). The side-effect barrel `src/sync/mutators/index.ts` registers every mutator module so that a scope-reset rebase can re-run pending commands locally (change request T06-003). The barrel does not import the comments module yet. Today the mutator is registered as soon as a screen that shows a comment thread is loaded, because `CommentThread` imports it, but a rebase that happens before any such screen has been opened would not re-apply a pending comment locally until the server answers.

## Proposed change

```diff
--- a/apps/mobile/src/sync/mutators/index.ts
+++ b/apps/mobile/src/sync/mutators/index.ts
@@
 import "./assets";
+import "./comments";
 import "./jobs";
 import "./media";
```

## Workaround in place
`src/features/comments/CommentThread.tsx` imports `../../sync/mutators/comments`, so the mutator is registered whenever a work-order, report or rental detail screen is opened. The outbox row itself is durable either way; only the optimistic re-apply after a rebase is affected.

## Impact if rejected
After a scope reset, a queued offline comment may disappear from the thread until the push succeeds and the server row is pulled back.

## Resolution

Applied by the W6 gate together with T15-002: the mobile mutator barrel imports `./comments` and `./fuel`. `apps/mobile/test/ui/moreScreen.test.tsx` asserts that `comment.create` is registered.
