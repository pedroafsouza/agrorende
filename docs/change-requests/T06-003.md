# T06-003 · Register the mobile report mutators at app start

Status: OPEN
Requested by: T06 · Wave: W3
Target: `apps/mobile/src/sync/mutators/index.ts` (new) or the session bootstrap in `apps/mobile/src/lib/session*` (owner: T03)
Kind: other

## Problem
`defineMutator` registers a mutator when its module is imported. `apps/mobile/src/sync/mutators/reports.ts` is imported by the report screens and routes, but nothing imports it at app start. If the app restarts with a pending `fieldReport.*` command and the user does not open a report screen, a scope-reset rebase cannot re-run the mutator locally.

## Proposed change
Add a side-effect barrel `apps/mobile/src/sync/mutators/index.ts` that imports every mutator module (`./assets`, `./media`, `./reports`, and the ones peers add), and import it once from the session bootstrap before the engine starts.

Also delete the T01 placeholder `apps/mobile/src/sync/mutators/fieldReports.ts` (`createFieldReport`, `updateFieldReport` and `withdrawFieldReport` all throw `notImplemented`), or turn it into `export { createReport as createFieldReport, updateReport as updateFieldReport, withdrawReport as withdrawFieldReport } from "./reports";`. Nothing imports it today.

## Workaround in place
The report routes import the mutator module through `features/reports`. Push does not need the mutator, because the outbox row already carries the payload, so only the local rebase path is affected.

## Impact if rejected
After a scope reset, an unsent report is missing from the local mirror until the user opens a report screen or the push succeeds and the server row is pulled.
