# T08-001 · Wire the rental seams, enable JSX in core and small rental follow-ups

Status: APPLIED
Requested by: T08 · Wave: W3
Target: `packages/core/src/seams.ts` (owner: T01), `packages/core/tsconfig.json` (owner: T01), `packages/core/src/pdf/index.ts` (owner: T01), `packages/contracts/src/mutations/rentals.ts` (owner: T01), `apps/worker/src/processors.ts` (owner: T05), `apps/mobile/src/features/home/widgets.ts` (owner: T03)
Kind: seam signature · other

## Problem

1. **Rental seams are still stubs.** `packages/core/src/seams.ts` defines `markRentalDamagesRepaired` and `activeRentalForAsset` as `notImplemented(...)`. T07 (work-order completion) and T06 (linking a report to the active rental) therefore get `INTERNAL NOT_IMPLEMENTED` at runtime. T08 implemented both in `packages/core/src/modules/rentals/service.ts` (`markDamagesRepaired`, `activeRentalForAsset`), with tests in `modules/rentals/mutations.test.ts` ("seams" block).
2. **Core has no `jsx` setting.** `packages/core/tsconfig.json` does not set `jsx`, so importing `src/pdf/rentalCheckout.tsx` or `rentalCheckin.tsx` from a `.ts` file raises `TS6142: Module was resolved to '…tsx', but '--jsx' is not set`. `apps/web` does set `jsx`, so a `@ts-expect-error` becomes "unused" (`TS2578`) when web typechecks the same files. T08 therefore uses `// @ts-ignore`, together with an ESLint disable for `@typescript-eslint/ban-ts-comment`, in `modules/rentals/queries.ts` and `pdf/rentalCheckin.tsx`. `src/modules/workOrders/report.ts` (T07) has the same problem, and the web typecheck reports it as `TS2578`.
3. **The check-in payload has no way to confirm a large meter jump.** `rental.checkin` rejects with `METER_READING_JUMP` when the hour-meter delta is greater than elapsed hours + 1 (EC-RN-27). The only bypass is `meterReplaced: true` with `meterPhotoMediaId`. There is no "confirmed by agent" flag for a genuine jump, such as a meter that was not read at check-out.
4. **`pdf/index.ts` is still a stub.** `renderRentalDocument` throws `notImplemented("pdf.renderRentalDocument")`, while `renderRentalPdf(ctx, rentalId, kind)` in `modules/rentals/queries.ts` is implemented.
5. **`apps/worker/src/processors.ts` has a placeholder.** It contains a `"rentals.overdueScan"` entry that returns `undefined`. The real job is `apps/worker/src/jobs/rentals.overdueScan.ts`, which `jobs/index.ts` picks up through `PEER_JOB_OWNERS`. The placeholder is dead code and could shadow the real job if both registries are consulted.
6. **The Today screen shows the shell card.** `apps/mobile/src/features/home/widgets.ts` re-exports `RentalsTodayCard` from `./cards`, which is the T03 shell placeholder, instead of the T08 widget in `../rentals/widgets` (DELIVERY-PLAN §4 widget contract).

## Proposed change

1. In `packages/core/src/seams.ts`:

   ```ts
   import * as rentalsService from "./modules/rentals/service.js";

   export async function markRentalDamagesRepaired(tx: Tx, input: { workOrderId: string; damageIds: string[] }): Promise<void> {
     return rentalsService.markDamagesRepaired(tx, input);
   }

   export async function activeRentalForAsset(tx: Tx, assetId: string): Promise<{ id: string; number: string } | null> {
     return rentalsService.activeRentalForAsset(tx, assetId);
   }
   ```

   `rentals/mutations.ts` imports `createFieldReportFromDamage` from `seams.js`, so this creates an import cycle. The cycle is safe, because every use happens at call time, which matches how the other modules are wired.
2. Add `"jsx": "react-jsx"` to `packages/core/tsconfig.json` (`compilerOptions`). Then remove the `@ts-ignore` and ESLint-disable pairs in `modules/rentals/queries.ts` and `pdf/rentalCheckin.tsx`, plus the `@ts-expect-error` in `modules/workOrders/report.ts`.
3. Add `meterJumpConfirmed: z.boolean().optional()` to `InspectionBaseSchema` in `packages/contracts/src/mutations/rentals.ts`. T08 will then skip the jump guard when the flag is true and write a `rental.meterJumpConfirmed` attention activity.
4. Make `renderRentalDocument` in `pdf/index.ts` delegate to `renderRentalPdf` from `modules/rentals/queries.ts`, or remove it.
5. Remove the `"rentals.overdueScan"` placeholder from `apps/worker/src/processors.ts`.
6. In `apps/mobile/src/features/home/widgets.ts`, export `RentalsTodayCard` from `../rentals/widgets` instead of `./cards`.

## Workaround in place

- Seams: T08 callers use `modules/rentals/service.ts` directly. T07 and T06 can import `markDamagesRepaired` and `activeRentalForAsset` from `@agrorende/core/modules/rentals/service` until the seam is wired.
- JSX: `// @ts-ignore` with an ESLint disable, so both the core and web typechecks pass.
- Meter jump: agents use `meterReplaced` with a photo, or the office corrects the reading afterwards.
- Worker: the real job is registered through `jobs/index.ts`.
- Mobile: the T08 `RentalsTodayCard` is exported from `src/features/rentals/widgets.tsx` and is ready to be swapped in.

## Impact if rejected

- Work-order completion never marks rental damages as repaired, so assets stay NEEDS_REPAIR.
- Field reports are not linked to the active rental.
- The `@ts-ignore` comments stay in place.
- A genuine meter jump cannot be confirmed in the field.
- The Today screen keeps showing the placeholder rentals card.

## Resolution

The orchestrator applied all six items at the W3 gate. (1) `markRentalDamagesRepaired` and `activeRentalForAsset` in `packages/core/src/seams.ts` delegate to `rentalsService.markDamagesRepaired` and `rentalsService.activeRentalForAsset`; the resulting import cycle is safe because every use happens at call time. (2) Core now compiles JSX with `"jsx": "react-jsx"` and the `@ts-ignore` workarounds are gone (see T07-004). (3) `InspectionBaseSchema` gained an optional `meterJumpConfirmed` boolean; `rentals/inspections.ts` skips the jump guard when it is true, and instead of a separate `rental.meterJumpConfirmed` activity the existing `rental.checkedIn` activity carries `meterJumpConfirmed: true` and `attention: true` in its meta, which keeps one activity per check-in. A new test in `modules/rentals/mutations.test.ts` covers the confirmed jump. The field UI that sends the flag is a T10 gap. (4) `renderRentalDocument` in `pdf/index.ts` now lazy-imports and delegates to `renderRentalPdf` from `modules/rentals/queries.ts`. (5) The legacy `apps/worker/src/processors.ts` and `apps/worker/src/queues.ts` were deleted outright, because the live worker path is `jobs/index.ts` and nothing else imported them; `jobRegistry.test.ts` no longer asserts on `JOB_PROCESSORS`. (6) `RentalsTodayCard` is exported from `../rentals/widgets` in the mobile home widgets.
