# T06-001 · Wire the `createFieldReportFromDamage` seam to the field reports module

Status: OPEN
Requested by: T06 · Wave: W3
Target: `packages/core/src/seams.ts` (owner: T01 / orchestrator)
Kind: seam signature

## Problem
`seams.ts` still throws `notImplemented("seams.fieldReports.createFromDamage")` from `createFieldReportFromDamage`. Rentals (T08) calls this seam in `packages/core/src/modules/rentals/mutations.ts` when a return inspection records damage (FR-F1 return-damage path, EC-RNT damage → report). T06 cannot edit `seams.ts`.

## Proposed change
```ts
import { createFromDamage } from "./modules/fieldReports/service.js";

export async function createFieldReportFromDamage(
  tx: Tx,
  ctx: Ctx,
  damage: { damageId: string; rentalId: string; assetId: string },
): Promise<{ id: string; number: string }> {
  return createFromDamage(tx, ctx, damage);
}
```
The signature is unchanged. `createFromDamage` is idempotent per `damageId` (a second call returns the existing report), creates the report as SUBMITTED with `source: "RENTAL_DAMAGE"`, `priority: HIGH`, links `damageId` and `rentalId`, and copies the damage media references.

## Workaround in place
`packages/core/src/modules/fieldReports/service.ts` exports `createFromDamage`, covered by `service.test.ts`. Nothing in T06 depends on the seam itself.

## Impact if rejected
A damaged return does not open a field report automatically; the office would have to report the damage by hand.
