# T09-002 · Shared realtime subscription and map ref for the Ops Center

Status: OPEN
Requested by: T09 · Wave: W3
Target: `apps/web/src/features/shell/useRealtime.ts`, `apps/web/src/components/map/MapView.tsx` (owner: T04)
Kind: seam signature

## Problem
DELIVERY-PLAN §5 T09 asks for live updates "via `useRealtime()`" and layers "registered via `useMapLayers`". Neither seam is enough for the Ops Center:

- `useRealtime(enabled)` returns only the connection state. It gives no way to subscribe to `operator:location`, `operator:presence` or `activity:new`, and no way to know when a reconnect happened.
- `MapView` exposes no `MapRef`. The Ops Center needs one to call `getSource("ops-operators").setData(frame)` once per animation frame. Updating React props for 300 markers would re-render every marker on every fix.
- `MapView` has no `onError` hook for EC-OPS-18 `MAP_TILES_UNAVAILABLE` and no `onLoad` hook for registering shape images.

## Proposed change
1. Have `useRealtime` keep its single socket and also export `useRealtimeEvent(event: RealtimeServerEvent, handler: (payload: unknown) => void)`, plus `useRealtimeStatus(): { state, lastMessageAt: Date | null, reconnectCount: number }`.
2. Make `MapView` forward its ref (`forwardRef<MapRef, MapViewProps>`) and accept `onError`, `onLoad`, `onClick` and `interactiveLayerIds` props that it passes through to react-map-gl `Map`.

## Workaround in place
- `apps/web/src/features/ops/realtime.ts` opens a dedicated Ops Center socket. It uses the same `/auth/socket-token` flow, accepts an injectable `OpsSocketFactory` for tests, and exposes `useOpsRealtime(factory, handlers)` returning `{ state, lastUpdateAt, paused }`.
- `apps/web/src/features/ops/OpsMap.tsx` renders react-map-gl `Map` directly with the clustered sources, the frame-loop operator source and the tile-error banner.

The admin tab therefore holds two sockets while the Ops Center is open.

## Impact if rejected
The Ops Center keeps a second socket per tab and its own map component. Behaviour is unchanged.
