# T13-001 · Declare the simulator's runtime dependencies in the worker

Status: OPEN
Requested by: T13 · Wave: W5
Target: apps/worker/package.json, pnpm-lock.yaml (owner: T01)
Kind: dependency

## Problem

ARCHITECTURE §3.4 states that the worker uses `@agrorende/api-client` and `socket.io-client`
for `pnpm simulate`, but `apps/worker/package.json` declares neither. The simulator in
`apps/worker/src/simulate.ts` works today only because pnpm is configured with
`nodeLinker: hoisted`, so `socket.io-client` happens to be reachable from the root
`node_modules`, and because the api-client is imported by a relative path. A change to the
linker mode, or a stricter dependency lint, would break `pnpm simulate`.

## Proposed change

Add the two packages to the `dependencies` of `apps/worker/package.json` and refresh the
lockfile:

```diff
   "dependencies": {
+    "@agrorende/api-client": "workspace:*",
     "@agrorende/contracts": "workspace:*",
     "@agrorende/core": "workspace:*",
     "@agrorende/db": "workspace:*",
     "bullmq": "^6.3.11",
     "expo-server-sdk": "^7.2.0",
     "ioredis": "catalog:",
-    "pino": "catalog:"
+    "pino": "catalog:",
+    "socket.io-client": "catalog:"
   },
```

Then, in `apps/worker/src/simulate.ts`, replace

```ts
import { AgrorendeApiClient, isApiError } from "../../../packages/api-client/src/index.js";
```

with

```ts
import { AgrorendeApiClient, isApiError } from "@agrorende/api-client";
```

and delete the comment above it.

## Workaround in place

`simulate.ts` imports the api-client source through the relative path
`../../../packages/api-client/src/index.js`. This path typechecks because the worker
`tsconfig.json` uses `rootDir: "../.."`. It imports `socket.io-client` through hoisting. Both
`pnpm --filter worker typecheck` and `pnpm --filter worker lint` pass.

## Impact if rejected

`pnpm simulate` keeps working while the linker stays `hoisted`, but the worker's manifest does
not describe what it uses, and the relative import bypasses the package boundary.
