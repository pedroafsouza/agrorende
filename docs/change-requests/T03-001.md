# T03-001 · Make `expo export --platform android` bundle the mobile app

Status: APPLIED
Requested by: T03 · Wave: W2
Target: `apps/mobile/app.config.ts`, `apps/mobile/metro.config.js` (new), `apps/mobile/package.json`, `pnpm-lock.yaml` (owner: T01)
Kind: dependency

## Problem
The T03 acceptance criterion `pnpm --filter mobile exec expo export --platform android` fails before any T03 code is bundled. There are three independent blockers, found in that order:

1. `app.config.ts` lists `"expo-crypto"` as a config plugin. `expo-crypto` ships no `app.plugin.js`, so Expo loads the package main entry, which imports `expo-modules-core` under Node and crashes:

   ```
   PluginError: Cannot find module '.../node_modules/expo-modules-core/build/ts-declarations/global' imported from .../node_modules/expo-modules-core/build/index.js
   No "app.plugin.{js,cjs,mjs,ts,cts,mts}" file was found in "expo-crypto", so the package's main entry was loaded instead.
   ```

2. There is no `apps/mobile/metro.config.js` (it is listed as a T01 path in DELIVERY-PLAN §3.3). The workspace packages (`@agrorende/contracts`, `@agrorende/api-client`, …) use NodeNext-style relative imports ending in `.js` that point at `.ts` sources, which Metro cannot resolve without a resolver hook.

3. `react-native-reanimated@^4` requires its peer `react-native-worklets`, which is not installed. `react-native-gesture-handler` imports Reanimated, so every bundle that uses gesture-handler (which expo-router does) fails:

   ```
   Error: Unable to resolve module react-native-worklets from .../node_modules/react-native-reanimated/src/initializers.native.ts: react-native-worklets could not be found within the project or in these directories:
     ../../node_modules
   ```

## Proposed change
- Remove `"expo-crypto"` from the `plugins` array in `apps/mobile/app.config.ts`. The module needs no config plugin.
- Add `apps/mobile/metro.config.js`:

  ```js
  const { getDefaultConfig } = require("expo/metro-config");

  const config = getDefaultConfig(__dirname);
  const defaultResolve = config.resolver.resolveRequest;

  config.resolver.resolveRequest = (context, moduleName, platform) => {
    const resolve = defaultResolve ?? context.resolveRequest;
    if (moduleName.startsWith(".") && moduleName.endsWith(".js")) {
      try {
        return resolve(context, moduleName.slice(0, -3), platform);
      } catch {
        // Fall through to the original specifier.
      }
    }
    return resolve(context, moduleName, platform);
  };

  module.exports = config;
  ```

- Add `react-native-worklets` to `apps/mobile/package.json` at the version matching the installed Expo SDK (`npx expo install react-native-worklets`), and refresh the lockfile.

## Workaround in place
None is possible inside T03 paths. T03 verified fixes 1 and 2 on a scratch copy under `.data/t03-export` (ignored), where bundling then progresses to blocker 3. T03 removed its only direct Reanimated import (`src/ui/BottomSheet.tsx` now reads the reduce-motion setting through `AccessibilityInfo`), but gesture-handler still pulls Reanimated in.

## Impact if rejected
The Android bundle-only AC stays red for T03 and for every later mobile task, and no EAS build can be produced.

## Resolution
Applied at the W2 gate. The `expo-crypto` entry was removed from the `plugins` array in `apps/mobile/app.config.ts`. A Metro configuration was added as `apps/mobile/metro.config.cjs`, because the package is an ES module and Metro loads the configuration with `require`. Its resolver retries relative `.js` specifiers without the extension so that the TypeScript sources of the workspace packages resolve. `react-native-worklets` was installed with `expo install` so that its version matches the SDK. `pnpm --filter mobile exec expo export --platform android` now exits 0.
