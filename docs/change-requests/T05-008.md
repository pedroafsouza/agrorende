# T05-008 · User notification mute settings

Status: APPLIED
Requested by: T05 · Wave: W2
Target: `packages/db/src/schemas/index.ts` `UserSchema`, `packages/contracts` user DTO (owner: T01)
Kind: schema

## Problem
ARCHITECTURE §10 says `notifications.push` respects user mute settings, but `User` has no such field.

## Proposed change
Add `notificationPrefs: { pushMuted: boolean; mutedTypes: NotificationType[] }` (default `{ pushMuted: false, mutedTypes: [] }`) to `User`. The push job would then skip those users or types.

## Workaround in place
The push job sends to every active user who has an `OK` device token.

## Impact if rejected
Users cannot mute push notifications.

## Resolution
Deferred to T10. Mute settings need a new `notificationPrefs` field on the T01 `User` schema and DTO, a settings UI on web and mobile, and a migration default. That is a cross-cutting product change better made in the T10 hardening pass than at a wave gate. Until then the push job keeps sending to every active user with an `OK` device token, which is the documented workaround.

## T10 resolution

Applied in T10. `packages/db` `UserSchema` gains `notificationPrefs` (`{ pushMuted: boolean; mutedTypes: NotificationType[] }`, default `{ pushMuted: false, mutedTypes: [] }`), and the stored `User` type keeps the field optional so older documents still read. Migration `0002-T05-008` backfills the default on users without the field and is registered in `migrations/runner.ts`; the seed writes it explicitly. `packages/contracts/src/dto/users.ts` adds `NotificationPrefsSchema`, `notificationPrefsOf`, `SelfUserDTOSchema` (the user's own view, which carries the prefs) and `UpdateMeInputSchema`, where `notificationPrefs` is an optional partial patch next to `locale`. `PATCH /me` persists the prefs through `modules/users/notificationPrefs.ts` and bumps `syncVersion`; `GET /auth/me` returns the effective prefs, and other users' DTOs do not expose them. The `notifications.push` worker job skips a recipient whose `pushMuted` is true or whose `mutedTypes` contains the notification type; the in-app notification is still created and the row is still marked as pushed so it is not retried. The admin web settings page and the mobile settings screen each show a "mute push notifications" switch; on mobile the switch is online-only and shows an error state with retry when offline. Per-type mutes are supported by the API but not yet exposed in either UI.
