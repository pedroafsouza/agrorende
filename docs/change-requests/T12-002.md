# T12-002 · Wire the sync-attention and pending-work helpers into the mobile screens

Status: APPLIED-PARTIAL
Requested by: T12 · Wave: W5
Target: `apps/mobile/app/**` Sync Center, Home banner, Settings → Conta (owner: T03)
Kind: other

## Problem
T12 found several EC-SYN and EC-PLT behaviours that existed only partly in the client. It added pure logic for them, and the chaos suite tests that logic, but the screens do not render it yet:

- `src/sync/attention.ts` `syncAttention(db, snapshot, options)` derives the EC-SYN-01, 02, 25, 27, 28, 29, 30 and 31 attention codes (`OUTBOX_BACKLOG`, `OUTBOX_ITEM_STUCK`, `WIFI_ONLY_MEDIA_WAITING`, `MEDIA_PENDING_STALE`, `LOCATION_BUFFER_TRIMMED`, `DEVICE_UNSYNCED_STALE`, `UPLOAD_RESUME_AFTER_RESTART`, `SAME_USER_MULTIPLE_DEVICES`).
- `src/sync/handoff.ts` `collectPendingWork(db)` builds the "Salvar cópia" export for EC-PLT-42 and EC-SYN-12 as a JSON document.
- `syncStore.locationTrimmed` is now set by the location hook in `src/lib/app/session.ts`.

## Proposed change
1. Sync Center and the Home banner call `syncAttention` and show each code with `useRecovery(code)`.
2. The C6 reauthentication banner shows the number of pending items (`pendingItemCount`).
3. Settings → Conta adds "Enviar agora" (force a cycle that also allows mobile data once for media) next to "Salvar cópia". The pending-data sheet should share `collectPendingWork` and offer it as a zip with the media files.
4. EC-SYN-31 needs the list of the user's other devices with pending work from the server. Today `syncAttention` takes `otherDevicesWithPending` as an input.

## Workaround in place
The logic is in `src/sync/attention.ts` and `src/sync/handoff.ts` and is fully tested by `test/sync/chaos/errors.test.ts` and `round4.test.ts`. No screen calls it yet.

## Impact if rejected
The operator sees no banner for stale media, the trimmed location history or a stuck queue. The data is safe, but the recovery hints of ERRORS.md are not visible.

## Resolution

Applied at the W5 gate, with two parts left for a later task.

What changed:

- `src/features/sync/SyncAttention.tsx` adds `useSyncAttention()` (calls `syncAttention` through `useLocalQuery`; `coldStart` is true until the first sync of this process completes) and `SyncAttentionBanners`, which renders one dismissible `ErrorBanner` per code with the `useRecovery` handlers: retry runs `syncNow`, handoff runs "Salvar cópia", and the alternative action of `WIFI_ONLY_MEDIA_WAITING` sends with mobile data once.
- Sync Center renders every attention code (except the one already shown as the last error). The Home screen renders `OUTBOX_BACKLOG`, `DEVICE_UNSYNCED_STALE` and `LOCATION_BUFFER_TRIMMED` (`HOME_ATTENTION_CODES`).
- The C6 reauthentication banner on Home now shows the number of pending items (`ui.home.reauthPending`, ICU plural) using `pendingItemCount`.
- Settings → Conta shows the pending count and, when there is pending work, "Enviar agora" (`sendEverythingNow`: `allowMobileDataForAll` in `src/media/queue.ts`, then a forced sync cycle) and "Salvar cópia" (`savePendingWorkCopy`: writes the `collectPendingWork` JSON to the cache directory and opens the share sheet). The delete-account guard also uses `sendEverythingNow`.
- New keys exist in pt-BR and en (`sync.action.sendNow`, `sync.action.saveCopy`, `sync.copy.*`, `sync.attention.title`, `ui.home.reauthPending`, `settings.account.pending`, `settings.account.sendNowHint`).
- `test/ui/syncAttention.test.tsx` covers the reauth count, the Home and Sync Center banners, "Enviar agora" clearing the Wi-Fi-only flag and starting a cycle, and "Salvar cópia" sharing a manifest that lists the outbox and the media file paths.

Still open (for the owner of mobile sync, T03/T12 follow-up):

1. "Salvar cópia" shares the JSON manifest only, which lists the local media paths. It does not bundle the media files into a zip, because no zip library is in the mobile dependency set.
2. `SAME_USER_MULTIPLE_DEVICES` (EC-SYN-31) still needs a server source for `otherDevicesWithPending`; the screens pass none, so that banner never appears.
3. The sync store does not know whether the connection is Wi-Fi, so `WIFI_ONLY_MEDIA_WAITING` is evaluated as if the phone is not on Wi-Fi.
