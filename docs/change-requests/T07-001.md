# T07-001 · Delegate the work order seams to `modules/workOrders/service.ts`

Status: OPEN
Requested by: T07 · Wave: W3
Target: `packages/core/src/seams.ts` (owner: T01, frozen foundation)
Kind: seam wiring

## Problem
`workOrderSeams` in `packages/core/src/seams.ts` still throws `notImplemented` for `createFromSource`, `openCountByAssignee`, `maintenanceStatus` and `billingSnapshot`. T06 (`markForRepair`), T08 (damage jobs and billing), T09 (load per technician) and later T14 and T15 call these through the seam object, so every caller fails at runtime until the seam delegates to the T07 implementation.

## Proposed change
Replace the four stub bodies with delegation to the T07 module and keep the frozen signatures:

```ts
import * as workOrders from "./modules/workOrders/service.js";

export const workOrderSeams = {
  createFromSource: (tx, ctx, input) => workOrders.createFromSource(tx, ctx, input),
  openCountByAssignee: (tx, orgId) => workOrders.openCountByAssignee(tx, orgId),
  maintenanceStatus: (tx, planId, assetIds) => workOrders.maintenanceStatus(tx, planId, assetIds),
  billingSnapshot: (tx, workOrderId) => workOrders.billingSnapshot(tx, workOrderId),
} satisfies WorkOrderSeams;
```

If the static import creates a cycle (the T07 service imports `rentalSeams` from `seams.ts`), use a lazy `await import("./modules/workOrders/service.js")` inside each wrapper instead.

## Workaround in place
The four functions are exported from `packages/core/src/modules/workOrders/service.ts`. `service.test.ts` assigns them to a `WorkOrderSeams` value, so the compiler proves that they match the frozen contract. Callers in the same wave mock the seam (R12).

## Impact if rejected
Marking a field report for repair, damage repair jobs, billing snapshots and maintenance status keep failing with `NOT_IMPLEMENTED` outside unit tests.
