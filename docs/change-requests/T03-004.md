# T03-004 · Ownership of unlisted mobile paths written by T03

Status: OPEN
Requested by: T03 · Wave: W2
Target: `docs/DELIVERY-PLAN.md` §3.3 (owner: human / orchestrator); `apps/mobile/src/i18n/*/enums.json` (unowned)
Kind: other

## Problem
T03 needed these paths, but DELIVERY-PLAN §3.3 does not assign them to any task:

- `apps/mobile/app/index.tsx`: without an index route, opening the app shows expo-router's unmatched-route screen. It redirects to `/today` when signed in (this works offline from the cached profile) and to `/login` otherwise.
- `apps/mobile/jest.config.js`: the `test` script (`jest --runInBand`) needs a config with an `engine` project (Node) and a `ui` project (`jest-expo`).
- `apps/mobile/src/i18n/{messages,resources,runtime,useT,pseudo}.ts`: the i18n runtime (locale resolution, offline switch, pseudo-locale, typed `useT`). §3.3 assigns `src/i18n/index.ts` and the T03 JSON namespaces to T03 but does not mention these siblings. `messages.ts` came from T01 and was extended.
- `apps/mobile/src/i18n/*/enums.json`: shipped by T01, owned by nobody. T03 needed asset condition and media tag labels, so it put them in its own namespaces (`assets.condition.*`, `media.tag.*` under `common`) instead of editing `enums.json`.

## Proposed change
Add the four items above to the T03 row of §3.3. Either assign `enums.json` to T03, or record that enum labels live in the owning feature namespaces.

## Workaround in place
The files exist and pass `pnpm check:only mobile`. No other task's file was edited.

## Impact if rejected
Another owner must take over the files. If `app/index.tsx` is removed, the app opens on the unmatched-route screen.
