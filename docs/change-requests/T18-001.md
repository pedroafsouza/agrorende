# T18-001 · Exclude nested developer folders from the Docker build context

Status: OPEN
Requested by: T18 · Wave: W5
Target: `.dockerignore` (owner: T01)
Kind: other

## Problem

T18.1 asks T18 to validate that the frozen root `.dockerignore` excludes `.data/`, caches, local
env files, generated mobile native folders, coverage and `node_modules`. The current file only
matches several of these at the repository root:

- `node_modules` matches the root folder only. Every workspace package has its own
  `node_modules` (for example `apps/web/node_modules`, `packages/core/node_modules`) with symlinks
  and host binaries (macOS arm64 on developer machines) that would be copied into the builder
  stage and shadow the Linux install.
- `.env` and `.env.*` match the root only; an `apps/mobile/.env` or `apps/web/.env.local` would be
  sent to the Docker daemon and land in the builder layer.
- `.data` matches the root only; `apps/*/.data` test folders are sent.
- `.expo`, `.turbo` and `*.tsbuildinfo` are not excluded at all.

These files never reach the final images (the runtime stages copy only build output), but they
slow every build, can break `pnpm install` in the builder and expose local secrets to the build
cache.

## Proposed change

Replace the matching lines of `.dockerignore` with recursive patterns:

```diff
-node_modules
+**/node_modules
 .git
 .github
-.data
-.env
-.env.*
-!.env.example
+**/.data
+**/.env
+**/.env.*
+!**/.env.example
 **/.next
+**/.expo
+**/.turbo
+**/*.tsbuildinfo
 **/dist
 **/coverage
```

## Workaround in place

`infra/docker/clean-context.sh` runs as the first step of the `source` stage of every app
Dockerfile (`apps/web/Dockerfile`, `apps/realtime/Dockerfile`, `apps/worker/Dockerfile`) and
deletes nested `node_modules`, `.data`, `.next`, `.expo`, `.turbo`, `coverage`, env files other
than `.env.example`, and `*.tsbuildinfo` before `pnpm install`. Builds are correct, but the files
still travel to the Docker daemon and sit in the builder's `COPY . .` layer.

## Impact if rejected

Builds stay correct through the workaround, but local build contexts are larger and slower, and
local env files from nested folders are copied into the builder layer of local builds (never into
the runtime images, and CI checkouts have no such files).
