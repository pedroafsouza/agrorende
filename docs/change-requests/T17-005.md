# T17-005 · Update the wave 6 mount-point test for the real comment thread

Status: APPLIED
Requested by: T17 · Wave: W6
Target: `apps/mobile/test/ui/mountPoints.test.tsx` (owner: T10)
Kind: other

## Problem
T10 left `CommentThread` in `apps/mobile/src/features/comments` as a mount point that rendered nothing, and its test asserts exactly that. T17 replaced the stub with the real thread (FR/WO/RN comments with offline queueing), so the component now renders a list and an input, and the three rows fail:

```
● wave 6 mount points › CommentThread renders nothing for FIELD_REPORT
● wave 6 mount points › CommentThread renders nothing for WORK_ORDER
● wave 6 mount points › CommentThread renders nothing for RENTAL
```

## Proposed change
The patch below was applied to a scratch copy of the file and run with `npx jest`: all four rows pass.

```diff
--- a/apps/mobile/test/ui/mountPoints.test.tsx
+++ b/apps/mobile/test/ui/mountPoints.test.tsx
@@
-  it.each(["FIELD_REPORT", "WORK_ORDER", "RENTAL"] as const)("CommentThread renders nothing for %s", async (entityType) => {
+  it.each(["FIELD_REPORT", "WORK_ORDER", "RENTAL"] as const)("CommentThread mounts a thread for %s", async (entityType) => {
     const screen = await render(<CommentThread entityType={entityType} entityId={id} />);
-    expect(screen.toJSON()).toBeNull();
+    expect(screen.toJSON()).not.toBeNull();
   });
```

## Workaround in place
None is possible from T17's lane. The behaviour of the real thread is covered by `apps/mobile/test/ui/comments.test.tsx` (posting, offline pending state, read-only states).

## Impact if rejected
`pnpm check:only mobile` stays red on these three rows.

## Resolution

Applied by the W6 gate. `apps/mobile/test/ui/mountPoints.test.tsx` renders the real comment thread for each entity type with a test sync runtime and services, and expects its empty state, input and send button.
