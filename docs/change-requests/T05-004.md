# T05-004 · `expo-server-sdk` for the push job

Status: OPEN
Requested by: T05 · Wave: W2
Target: `apps/worker/package.json`, `pnpm-lock.yaml` (owner: T01)
Kind: dependency

## Problem
ARCHITECTURE §10 names `expo-server-sdk` for `notifications.push`, but the worker does not depend on it, and R4 forbids `pnpm add`.

## Proposed change
Add `expo-server-sdk` to `apps/worker` `dependencies`, then swap `createExpoFetchClient` for an SDK-backed `ExpoPushClient`. The interface stays the same.

## Workaround in place
`apps/worker/src/jobs/notifications.push.ts` implements a minimal client over `fetch` against `https://exp.host/--/api/v2/push/send` and `/getReceipts`. It sends batches of 100, uses `EXPO_ACCESS_TOKEN` when it is set, and maps `DeviceNotRegistered` from both tickets and receipts.

## Impact if rejected
The fetch client keeps working. It lacks the SDK's gzip support and its built-in chunk-size and token validation.
