# T02-002 · Export the platform HTTP handlers from `@agrorende/core`

Status: OPEN
Requested by: T02 · Wave: W2
Target: `packages/core/src/index.ts`, `packages/core/package.json` (owner: T01)
Kind: export

## Problem
The framework-free HTTP handlers for auth, sync, devices, media, users, notifications, settings, me, telemetry and health live in `packages/core/src/auth/api/` and are aggregated in `platformApi` (`auth/api/index.ts`). `@agrorende/core` exports neither that folder nor the auth service, so the web app cannot import them by package name.

## Proposed change
Add a subpath export `"./auth/api": "./src/auth/api/index.ts"` to `packages/core/package.json` (or `export * as platform from "./auth/api/index.js"` in `src/index.ts`), then change the import in `apps/web/src/app/api/v1/auth/_platform.ts` to `@agrorende/core/auth/api`.

## Workaround in place
`apps/web/src/app/api/v1/auth/_platform.ts` (`server-only`) imports `packages/core/src/auth/api/index` through a relative path, the same way `apps/web/src/lib/core.server.ts` (T04) reaches core modules. Every T02 route file goes through that adapter only.

## Impact if rejected
The relative import keeps working with Turbopack and tsc, but it bypasses the package boundary that ESLint is meant to enforce.
