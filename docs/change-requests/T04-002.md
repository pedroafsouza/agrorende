# T04-002 · Implement the shared `recordActivity` helper and domain events

Status: APPLIED
Requested by: T04 · Wave: W2
Target: `packages/core/src/activity/**`, `packages/core/src/events/**` (owner: T01)
Kind: seam signature

## Problem
`recordActivity` in `packages/core/src/activity` is a frozen `notImplemented` stub. Every state change must write an ActivityEvent (PLT-13), so calling the stub would make every master-data write fail.

## Proposed change
Implement `recordActivity(tx, row)` so that it inserts into `activity_events` with `organizationId`, `syncVersion`, `actorId`, `entityType`, `entityId`, `action`, `fromStatus`, `toStatus`, `meta`, `occurredAt` and `receivedAt`, following ARCHITECTURE §6. Implement the event emitter in the same way.

## Workaround in place
`packages/core/src/modules/assets/kit.ts` exports `writeActivity(tx, row)`, which writes the same document shape directly. The assets, sites, seasons, customers and checklists modules use it. When the shared helper lands, `writeActivity` can delegate to it.

## Impact if rejected
There would be two writers of the same collection. Both are correct today, but they could drift apart.

## Resolution
Applied at the W2 gate. `recordActivity(tx, row)` in `packages/core/src/activity/index.ts` inserts an `activity_events` document with the organisation id, a sync version, the actor, the entity type and id, the action, the from and to statuses, `meta`, `occurredAt` and `receivedAt`, following ARCHITECTURE §6. `writeActivity` in `packages/core/src/modules/assets/kit.ts` now delegates to it, so there is a single writer of the collection. The event emitter was implemented in the same pass; see change request T02-004.
