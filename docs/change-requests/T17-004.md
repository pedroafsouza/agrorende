# T17-004 · Prune annotated photo originals after upload

Status: OPEN
Requested by: T17 · Wave: W6
Target: `apps/mobile/src/lib/app/session.ts` (owner: T03)
Kind: other

## Problem
FR-04 photo annotation (T17) writes the flattened, annotated JPEG as `media/<id>_annotated.jpg` and points the `media_files` row's `localUri` and `thumbUri` at it, keeping the same media id. The unannotated original `media/<id>.<ext>` is kept on purpose until the upload has finished, so that an interrupted annotation never loses the photo. `pruneMediaFiles` only deletes the file named in `localUri`, so after upload the original is orphaned. T17 provides `pruneAnnotationOriginals(db, files)` in `src/components/MediaCapture/annotation.ts`, which deletes the originals of rows that are `DONE` and returns how many files it removed.

## Proposed change

```diff
--- a/apps/mobile/src/lib/app/session.ts
+++ b/apps/mobile/src/lib/app/session.ts
@@
 import { drainMediaQueue, pruneMediaFiles } from "../../media/queue";
+import { pruneAnnotationOriginals } from "../../components/MediaCapture/annotation";
@@
       // §7.7 step 8: DONE originals are kept 7 days, or removed at once when free space is low.
+      await pruneAnnotationOriginals(db, expoFileStore).catch(() => 0);
       await pruneMediaFiles(db, expoFileStore, Date.now(), await expoFileStore.freeBytes()).catch(() => 0);
```

## Workaround in place
None. The orphaned originals take the same space as the photos themselves; the low-storage guard (EC-PLT-14) still protects capture.

## Impact if rejected
Each annotated photo leaves one unannotated original on the phone after upload, until the app data is cleared.
