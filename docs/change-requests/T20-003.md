# T20-003 · Mount the tenancy banner in the web shell

Status: OPEN
Requested by: T20 · Wave: W3
Target: `apps/web/src/features/shell/OrgBanner.tsx` and the admin layout (owner: T04)
Kind: mount point

## Problem
T20.7 needs the role-aware trial, past-due, suspended and cancelled banner on every office page (EC-OPS-29). T20 built it as `TenancyOrgBanner` in `apps/web/src/features/tenancy/TenancyOrgBanner.tsx`, but the shell's `OrgBanner.tsx` still renders the T04 placeholder from `admin.orgStatus.*`.

## Proposed change
In the admin layout (a server component), read `supportWhatsApp()` from `@/features/tenancy/server` and pass it down. In `features/shell/OrgBanner.tsx`, render `<TenancyOrgBanner supportWhatsApp={supportWhatsApp} />` from `@/features/tenancy` in place of the current markup. The `tenancy` namespace is already part of `SHELL_NAMESPACES`.

The banner reads `org.pastDueAt` and `org.purgeAfter` from `/auth/me` when they are present. If `/auth/me` strips them, add both to the `org` object of the `/auth/me` response (owner T02).

## Workaround in place
None; the component is exported and tested (`features/tenancy/tenancy.test.tsx`) but not mounted.

## Impact if rejected
Office users do not see why the organisation is read-only or how to reactivate it.
