# T05-003 · Add `ON_HOLD` to `OperatorStateEnum`

Status: APPLIED
Requested by: T05 · Wave: W2
Target: `packages/contracts/src/realtime.ts` (owner: T01)
Kind: contract

## Problem
ARCHITECTURE §6.4 shows a held work order on the ops map, but `OperatorStateEnum` has no `ON_HOLD` value. `deriveOperatorState` cannot express it.

## Proposed change
Add `"ON_HOLD"` to `OperatorStateEnum`, between `WORKING` and `IDLE`. `deriveOperatorState` in `packages/core/src/modules/locations/state.ts` then returns `ON_HOLD` when the active work order is `ON_HOLD`; this is a one-line change.

## Workaround in place
A held work order maps to `IDLE`.

## Impact if rejected
On the ops map, an operator whose work order is on hold looks the same as an idle operator.

## Resolution
Applied at the W2 gate. `ON_HOLD` was added to `OperatorStateEnum` in `packages/contracts/src/realtime.ts`. `deriveOperatorState` in `packages/core/src/modules/locations/state.ts` maps an on-hold job to `ON_HOLD` instead of the earlier workaround, and its tests were updated to match.
