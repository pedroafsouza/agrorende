# T07-004 · JSX and React for `packages/core/src/pdf/**`

Status: APPLIED
Requested by: T07 · Wave: W3
Target: `packages/core/tsconfig.json`, `packages/core/eslint.config.js`, `packages/core/package.json` (owner: T01, frozen foundation)
Kind: build configuration

## Problem
ARCHITECTURE §4 lets `packages/core/src/pdf/**` use `@react-pdf/renderer`, and DELIVERY-PLAN §3 names the file `core/src/pdf/workOrderReport.tsx`. However:

- core's tsconfig has no `jsx` option, so JSX does not compile and a static import of any `.tsx` module fails with TS6142;
- `CORE_RESTRICTED` forbids `react` everywhere in core, including `src/pdf/**`, although `@react-pdf/renderer` cannot be used without React elements;
- `react` is not a declared dependency of core. It only resolves because `nodeLinker: hoisted` hoists the web and mobile copy.

## Proposed change
1. Add `"jsx": "react-jsx"` to `packages/core/tsconfig.json`.
2. Extend the `src/pdf/**` scoped allowance in `packages/core/eslint.config.js` to allow `react` as well as `@react-pdf/renderer`.
3. Add `react` (the workspace catalog version) to `packages/core` dependencies, as the peer dependency of `@react-pdf/renderer`.

## Workaround in place
`pdf/workOrderReport.tsx` contains no JSX. It builds elements with `createElement` taken from a lazy `import("react")`, typed through a local opaque element type. `modules/workOrders/report.ts` loads the renderer with a lazy import marked `@ts-expect-error TS6142`, and the file itself is still type-checked because it lies under `src`. A test renders a real PDF and checks the `%PDF-` header.

## Impact if rejected
The workaround keeps working, but it depends on React being hoisted and it hides the import from the lint rule. T08's rental documents need the same change.

## Resolution

The orchestrator applied this request at the W3 gate. `packages/core/tsconfig.json` now sets `"jsx": "react-jsx"`, `react` was added to the `packages/core` dependencies through the workspace catalog (the lockfile gained three lines and `pnpm install --frozen-lockfile` passes), and the core ESLint scoped allowance for `src/pdf/**` now permits both `@react-pdf/renderer` and `react`. The `@ts-ignore` and ESLint-disable pairs were removed from `modules/rentals/queries.ts`, `pdf/rentalCheckin.tsx` and `modules/workOrders/report.ts`; the lazy import of the work-order PDF stays because it keeps React out of the default core load path.
