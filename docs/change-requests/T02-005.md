# T02-005 · Move notification templates into `@agrorende/i18n`

Status: APPLIED
Requested by: T02 · Wave: W2
Target: `packages/i18n/src/messages/{pt-BR,en}/notifications.json` (owner: T01)
Kind: i18n

## Problem
Server-rendered notification title and body templates (ARCHITECTURE §6.5) belong in the `notifications` namespace of `@agrorende/i18n`, which T02 does not own.

## Proposed change
Copy `NOTIFICATION_TEMPLATES` from `packages/core/src/notify/templates.ts` into the `notifications` namespace for pt-BR and en (keys `<TYPE>.title` and `<TYPE>.body`), then make `renderNotification` read from `@agrorende/i18n`.

## Workaround in place
`packages/core/src/notify/templates.ts` holds both locales for every `NotificationType`, with a small ICU renderer (`{name}` and `plural`) and a test that every type has both locales.

## Impact if rejected
Translators must edit a TypeScript file, and `pnpm i18n:check` does not cover notification text.

## Resolution
Deferred to T10. Moving the notification templates into the `notifications` namespace of `@agrorende/i18n` changes a T01 translation catalogue and the way `renderNotification` loads messages on the server. That belongs with the T10 i18n and hardening pass, which also owns the catalogue coverage of `pnpm i18n:check`. The current workaround in `packages/core/src/notify/templates.ts` is complete, holds both locales for every notification type and is tested, so nothing is blocked in W3.

## T10 resolution
Applied by T10. The `notifications` namespace of `@agrorende/i18n` (`packages/i18n/locales/pt-BR/notifications.json` and `packages/i18n/locales/en/notifications.json`) now holds `<TYPE>.title` and `<TYPE>.body` for every `NotificationType`, copied verbatim from the former TypeScript map and merged with the existing `workOrder`, `sync` and `rental` keys. The small ICU renderer (`{name}` arguments and `plural` with `=N`, `one`, `other` and `#`) moved from core into the new `@agrorende/i18n/server` entry point (`packages/i18n/src/server.ts`), together with a typed server catalogue (`SERVER_MESSAGES`), a key lookup (`serverMessage`) and a locale resolver. No new dependency was added. `packages/core/src/notify/templates.ts` keeps its public API (`renderNotification`, `renderIcu`, `resolveNotificationLocale` and `NOTIFICATION_TEMPLATES`), but every text is now read from the catalogue, so the duplicated map is gone. `pnpm i18n:check` now fails when any `NotificationType` lacks `notifications.<TYPE>.title` or `notifications.<TYPE>.body` in a required locale, and the tests in `packages/core/src/notify/templates.test.ts` assert coverage and rendering for every type in both locales.
