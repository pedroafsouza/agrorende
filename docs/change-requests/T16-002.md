# T16-002 · Enable the shell search box as the command palette trigger

Status: APPLIED
Requested by: T16 · Wave: W6
Target: `apps/web/src/features/shell/AdminShell.tsx` (owner: T04), `apps/web/messages/*/admin.json` key `shell.searchSoon`
Kind: other

## Problem
OPS-08 (⌘K search and command palette) is delivered in `apps/web/src/features/command-palette/**`. The palette opens with Ctrl+K or ⌘K anywhere in the admin app, and other code can open it with the exported `openCommandPalette()`. The header search box in the admin shell is still `disabled`, with the placeholder "Search coming soon", so mouse and touch users have no visible way to open the palette.

## Proposed change
In `AdminShell.tsx` (around line 127), replace the disabled `<input>` with a button styled like the input that opens the palette:

```tsx
import { openCommandPalette } from "@/features/command-palette";
// ...
<button
  aria-keyshortcuts="Control+K Meta+K"
  className="min-h-12 w-full rounded-controls border border-[var(--ar-border)] bg-[var(--ar-bg)] pl-9 pr-3 text-left text-sm text-[var(--ar-text-muted)]"
  onClick={openCommandPalette}
  type="button"
>
  {t("shell.search")}
</button>
```

Change `shell.searchSoon` to say "Search or run a command (Ctrl+K)" (pt-BR: "Buscar ou executar um comando (Ctrl+K)") and use it as the button label, or remove it if it is no longer used.

## Impact if not applied
The palette works from the keyboard only. The visible search box stays disabled, which reads as an unfinished feature.

## Resolution

Applied by the W6 gate. The admin shell search box is a button that calls `openCommandPalette()` and announces the Ctrl+K and Meta+K shortcuts. `shell.searchSoon` now reads "Search or run a command (Ctrl+K)" and "Buscar ou executar um comando (Ctrl+K)". Covered by `apps/web/src/features/shell/AdminShell.test.tsx`.
