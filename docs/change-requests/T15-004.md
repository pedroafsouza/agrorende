# T15-004 · Type `costsRollup` with the real roll-up response

Status: APPLIED
Requested by: T15 · Wave: W6
Target: `packages/api-client/src/index.ts`, `packages/api-client/src/types.ts` (owner: T01, frozen)
Kind: types

## Problem
`AgrorendeApiClient.costsRollup(query)` is typed as `Promise<ListResponse<CostRollupRow>>` (`{ items, … }`). The route `GET /costs/rollup` returns `CostRollupDTO` from `packages/core/src/modules/costs/dto.ts`, which is `{ groupBy, rows, totals, … }`. Any typed client that reads `items` gets `undefined`.

## Proposed change
Add a `CostRollupResponse` interface to `packages/api-client/src/types.ts` (`groupBy: CostGroupBy; rows: CostRollupRow[]; totals: Omit<CostRollupRow, "key" | "label">`, plus optional `fuelLogCount?: number`) and change `costsRollup` to return `Promise<CostRollupResponse>`.

## Workaround in place
The mobile machine profile reads the response through the typed adapter `assetCostSummary(response, assetId)` in `apps/mobile/src/features/assets/logic.ts`. The adapter accepts both `rows` and `items` and picks the row whose `key` is the asset id.

## Impact if rejected
The adapter stays in place. Other typed callers keep a misleading return type.

## Resolution

Applied by the W6 gate. `CostRollupResponse` is added to `packages/api-client/src/types.ts`, and `costsRollup` returns it. The mobile `assetCostSummary` adapter keeps accepting the response unchanged.
