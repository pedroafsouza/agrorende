# T04-005 · Let `apps/web` build: resolve `.js` specifiers to TypeScript sources

Status: OPEN
Requested by: T04 · Wave: W2
Target: `apps/web/next.config.ts` (owner: T01)
Kind: other

## Problem
`pnpm --filter web build` (Next.js 16.3.8 with Turbopack) fails with 99 errors. Every one of them is either `Module not found: Can't resolve './dto.js'` (or `'../../errors.js'`, `'./client.js'` and so on) inside the transpiled workspace packages `@agrorende/contracts`, `@agrorende/db` and `@agrorende/core`, or an `Export <name> doesn't exist in target module` error that follows from it. The packages use ESM `.js` specifiers for `.ts` files, and `turbopack.resolveExtensions` does not map `.js` to `.ts`. `@agrorende/db` is also not listed in `transpilePackages`.

## Proposed change
- Add `"@agrorende/db"` to `transpilePackages`.
- Choose one of these options:
  - **Build with webpack.** Set `"build": "next build --webpack"` and add `webpack: (config) => { config.resolve.extensionAlias = { ".js": [".ts", ".tsx", ".js"] }; return config; }`.
  - **Keep Turbopack.** Map the specifiers in `turbopack.resolveAlias`, if the Turbopack version supports an extension alias.

## Workaround in place
None is possible inside T04's paths. Typecheck and lint pass with `moduleResolution: bundler`.

## Impact if rejected
The web app cannot produce a production build, which blocks deployment and T18.
