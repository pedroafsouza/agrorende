# T14-001 · Use the critical-window SLA when a work order gets its default due date

Status: OPEN
Requested by: T14 · Wave: W6
Target: `packages/core/src/modules/workOrders/service.ts` (owner: T07)
Kind: seam signature

## Problem

T14.5 asks that a job's default due date is halved when it is created inside a critical window of the season calendar that lists the asset's category (BR-F2-2, P1). T14 implemented this in its handover file `packages/core/src/modules/workOrders/sla.ts` as `dueAtFor(tx, orgId, assetCategory, createdAt, priority, settings, timeZone?)`, which loads `seasons.criticalWindowFor` lazily and calls `computeDueAt` with the window. The work-order service, which T14 does not own, still calls the synchronous `computeDueAt` without a window, so new jobs never receive the shorter due date.

## Proposed change

In `packages/core/src/modules/workOrders/service.ts`:

- Import `dueAtFor` from `./sla.js` next to `computeDueAt`.
- Line 221 (`createFromSource`): replace
  `computeDueAt(now, input.priority, settings.sla)`
  with
  `await dueAtFor(tx, ctx.orgId, asset?.category ?? null, now, input.priority, settings.sla, org.timezone)`,
  using the asset and organisation documents that the function already loads (or loading the asset category when `input.assetId` is set).
- Line 642 (`patch`, when `dueAt` is reset to `null`): replace
  `computeDueAt(wo.createdAt, input.priority ?? wo.priority, settings.sla)`
  with
  `await dueAtFor(tx, ctx.orgId, assetCategory, wo.createdAt, input.priority ?? wo.priority, settings.sla, org.timezone)`.

## Workaround in place

`dueAtFor` is exported and covered by `packages/core/src/modules/workOrders/sla.p1.test.ts` (halving inside a window, no change outside a window, other categories and jobs without an asset unaffected). Nothing calls it yet.

## Impact if rejected

BR-F2-2 (P1) stays partly unbuilt: jobs created during planting or harvest keep the normal SLA window.
