# T20-004 · Show the getting-started checklist on `/ops`

Status: APPLIED
Requested by: T20 · Wave: W3
Target: `apps/web/src/app/(admin)/ops/page.tsx` or `apps/web/src/features/ops/**` (owner: T09)
Kind: mount point

## Problem
TEN-01 asks for an onboarding checklist for new companies (machines, team, QR labels, app install). T20 built `GettingStartedPanel` in `apps/web/src/features/onboarding/GettingStartedPanel.tsx`. It renders only for ADMIN users, hides itself once every step is complete and needs the `tenancy` namespace, which the shell already loads.

## Proposed change
Render `<GettingStartedPanel />` from `@/features/onboarding` at the top of the Operations Center page, above the map.

## Workaround in place
Settings → Subscription also returns the checklist data; the panel is exported but not mounted.

## Impact if rejected
New administrators get no guided first steps after sign-up.

## Resolution

The orchestrator applied this request at the W3 gate. The Operations Center (`apps/web/src/features/ops/OpsCenter.tsx`) now renders `<GettingStartedPanel />` directly under the page header and above the map. The panel replaces T09's local `GettingStartedCard` copy and the `onboardingOf` helper that read `settings.onboarding`, so there is one onboarding checklist, owned by T20, which already limits itself to administrators.
