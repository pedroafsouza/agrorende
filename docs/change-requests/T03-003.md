# T03-003 · Home widget export names for T06, T07 and T08

Status: OPEN
Requested by: T03 · Wave: W2
Target: `apps/mobile/src/features/reports/**` (T06), `apps/mobile/src/features/jobs/**` (T07), `apps/mobile/src/features/rentals/**` (T08); `apps/mobile/src/features/home/widgets.ts` (T03)
Kind: seam signature

## Problem
ARCHITECTURE §13.2 has Today show a quick report, the next job, today's rentals and my reports. Those cards render data owned by T06–T08, and T03 cannot import modules that do not exist yet.

## Proposed change
Each feature task exports a zero-prop React component from its feature `index.ts`:

| Card | Export | Folder | Owner |
|---|---|---|---|
| Quick report | `QuickReportCard` | `src/features/reports` | T06 |
| My reports | `MyReportsCard` | `src/features/reports` | T06 |
| Next job | `NextJobCard` | `src/features/jobs` | T07 |
| Rentals today | `RentalsTodayCard` | `src/features/rentals` | T08 |

Each card handles its own loading, empty, error and offline states and reads only local SQLite. After they land, T03 or the orchestrator changes the one re-export line in `src/features/home/widgets.ts` to point at the feature folders. Role filtering stays in `src/features/home/registry.ts` (`homeWidgetsFor`).

## Workaround in place
`src/features/home/cards.tsx` provides link cards with the same names. Each opens the owning tab (`/reports/new`, `/jobs`, `/rentals`, `/reports`), so Today works now.

## Impact if rejected
Today shows navigation cards only, without live counts or next-job details.
