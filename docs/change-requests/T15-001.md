# T15-001 · Cover the fuel and billing routes and the live `fuelLog.create` handler in the tenancy suite

Status: APPLIED
Requested by: T15 · Wave: W6
Target: `packages/core/src/__tests__/tenancy.test.ts` (owner: T10)
Kind: test

## Problem
T15 implemented the `fuelLog.create` mutation handler and added the fuel-log and billing-document routes. The cross-tenant suite was written while these were P1 stubs, so it now fails in two places:

1. `sync push: org B device targeting org A > fuelLog.create` expects `UNKNOWN_MUTATION`. The real handler now answers `REJECTED` with `NOT_FOUND` (details `entityType: "ASSET"`), which is the isolated outcome the suite wants for every other mutation.
2. `route coverage > every route file and method is in the table, in the allowlist or a notImplemented stub` lists these T15 routes as missing (the other missing routes in that list belong to T14, T16 and T17):
   - `GET fuel-logs`, `POST fuel-logs`, `GET fuel-logs/consumption`
   - `GET billing-documents`, `POST billing-documents`, `GET billing-documents/preview`
   - `GET billing-documents/[id]`, `PATCH billing-documents/[id]`
   - `POST billing-documents/[id]/issue`, `POST billing-documents/[id]/pay`, `POST billing-documents/[id]/cancel`, `GET billing-documents/[id]/pdf`

## Proposed change
- Change the `fuelLog.create` row of the push table to `{ expected: "NOT_FOUND", payload: () => ({ id: randomUUID(), assetId: A.asset, liters: 10 }) }` and remove the "P1 stub" comment above it.
- Seed one org A billing document (`A.billingDocument`, status DRAFT, on `A.customer`) and one org A fuel log (`A.fuelLog`, on `A.asset`) in the fixture, then add REST rows:
  - `GET billing-documents/[id]`, `PATCH billing-documents/[id]`, the three `POST …/{issue,pay,cancel}` and `GET …/pdf` with `A.billingDocument` → 404 and org A unchanged;
  - `POST billing-documents` with `{ source: "WORK_ORDER", workOrderId: A.workOrder }` → 404; `GET billing-documents/preview?workOrderId=A.workOrder` → 404;
  - `GET billing-documents` and `GET fuel-logs` → 200 with no org A id in the body; `GET fuel-logs/consumption?assetId=A.asset` → 200 with `points: []`;
  - `POST fuel-logs` with `{ assetId: A.asset, liters: 10 }` → 404.

## Workaround in place
The same isolation is asserted inside T15's own module tests: `packages/core/src/modules/billing/service.test.ts` ("billing tenant isolation (PLT-13)") and `packages/core/src/modules/fuel/service.test.ts` ("isolates organisations…"). Both pass.

## Impact if rejected
`pnpm check:only @agrorende/core` stays red on the tenancy suite and the T15 routes are not part of the central cross-tenant guarantee.

## Resolution

Applied by the W6 gate. The tenancy suite seeds an organisation A billing document, fuel log, catalog part, warehouse and maintenance plan, covers every billing-documents and fuel-logs route, and expects `fuelLog.create` to answer `NOT_FOUND`. `fuelConsumption` now answers `NOT_FOUND` for an asset of another organisation instead of echoing its id.
