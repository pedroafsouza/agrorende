# T04-004 · Have `withApi` build the core ctx from the access token

Status: OPEN
Requested by: T04 · Wave: W2
Target: `apps/web/src/server/withApi.ts` (owner: T01)
Kind: other

## Problem
`ApiContext.core` is optional and is never filled, and `readSession` only checks that the cookies are present. A route cannot rely on a verified `orgId`, `userId` or role.

## Proposed change
In `withApi`, verify the `ar_access` cookie or the bearer token with `verifyAccessToken(token, JWT_SECRET)`. Then build `core: Ctx` from the claims, enforce `options.roles` (`FORBIDDEN`), and return `UNAUTHENTICATED` when the token is missing or invalid.

## Workaround in place
`authenticate()` in `apps/web/src/lib/core.server.ts` performs these steps inside the T04 routes, and its route wrapper uses it.

## Impact if rejected
Each owner of web routes has to repeat the token check.
