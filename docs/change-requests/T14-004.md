# T14-004 · Load the parts namespace on the work-order pages, and update two W6 placeholder tests

Status: OPEN
Requested by: T14 · Wave: W6
Target: `apps/web/src/features/work-orders/WorkOrdersIntl.tsx` (owner: T07, in W6 T17's work-orders paths); `apps/web/src/features/comments/mountPoints.test.tsx` (owner: T17)
Kind: translation

## Problem

1. The web `PartsPanel` and `ExternalCostPanel` that T14 owns (`apps/web/src/features/work-orders/parts/**`) use copy from the `parts` namespace (`messages/*/parts.json`). `WorkOrdersIntl` loads only `[...SHELL_NAMESPACES, "jobs"]`.
2. T10 created `ExternalCostPanel` as a placeholder that renders `null`. The T17 test `apps/web/src/features/comments/mountPoints.test.tsx:83` ("ExternalCostPanel renders nothing") asserts that placeholder. T14 has now implemented the real panel, so that one assertion fails as expected. The same file also asserts `BillingActions renders nothing`, which T15 has replaced, and that fails for the same reason.

## Proposed change

1. In `WorkOrdersIntl.tsx`, line 9, change the call to
   `loadMessages(locale, [...SHELL_NAMESPACES, "jobs", "parts"])`.
2. In `mountPoints.test.tsx`, delete the "ExternalCostPanel renders nothing" case. Its behaviour is now covered by `apps/web/src/features/work-orders/parts/panels.test.tsx`.

## Workaround in place

`apps/web/src/features/work-orders/parts/PartsMessages.tsx` wraps both panels in a nested `NextIntlClientProvider`. That provider merges the `parts` messages for `en` and `pt-BR` into the messages already in context, so the panels render correctly today. Once change 1 is applied the wrapper becomes a no-op and can be removed.

## Impact if rejected

1. The workaround remains. It ships the `parts` messages in the client bundle of the work-order page.
2. `pnpm check:only web` keeps failing on the obsolete placeholder assertion.
