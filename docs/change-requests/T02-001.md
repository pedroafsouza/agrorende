# T02-001 · Add `@node-rs/argon2` for password hashing

Status: APPLIED
Requested by: T02 · Wave: W2
Target: `packages/core/package.json`, `pnpm-lock.yaml` (owner: T01)
Kind: dependency

## Problem
ARCHITECTURE §5 and §22 specify argon2id through `@node-rs/argon2`, but `packages/core` does not depend on it. Foundations are frozen after T01 (R4), so T02 cannot add it.

## Proposed change
Add `"@node-rs/argon2"` to `packages/core` dependencies and switch `packages/core/src/auth/password.ts` `hashPassword`/`verifyPassword` to argon2id. Keep verification of the existing `scrypt$…` and seed `sha256:<hex>` formats and upgrade them to argon2id on the next successful login, which `password.ts` already does for the seed format.

## Workaround in place
`packages/core/src/auth/password.ts` hashes with `scrypt` from `node:crypto` (N=16384, r=8, p=1, 64-byte key, 16-byte salt) in the self-describing format `scrypt$<params>$<salt>$<hash>`. Seed hashes are verified and upgraded on login.

## Impact if rejected
Passwords remain protected by scrypt, which is a memory-hard KDF and acceptable, but the stack diverges from ARCHITECTURE.

## Resolution
Applied at the W2 gate. `@node-rs/argon2` (prebuilt binaries, so no native build step is needed) was added to `packages/core`, and `packages/core/src/auth/password.ts` now hashes new passwords with Argon2id (memory 19456 KiB, two iterations, parallelism one). `verifyPassword` still accepts the legacy formats: the `sha256:` hashes written by the demo seed in `packages/db/seed/index.ts` and any `scrypt$` hash written during W2. `needsRehash` reports every non-Argon2id hash, so a successful login upgrades the stored hash. The seed itself was left unchanged. A new `password.test.ts` covers hashing, verification of every format and the rehash rule. `arctic` was also added to `packages/core`, because T01 claimed it but it was missing, so that T10 can wire the OAuth providers.
