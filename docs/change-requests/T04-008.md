# T04-008 · Let theme variables drive the page colours, and scope the touch-target rule

Status: OPEN
Requested by: T04 · Wave: W2
Target: `apps/web/src/app/globals.css` (owner: T01)
Kind: other

## Problem
- **Colours.** `body` hard-codes `background: #f8f9fa` and `color: #1c1f23`, and `:root` forces `color-scheme: light`. As a result, the dark and outdoor themes defined in `src/components/shell/theme.css` (`[data-theme]`, `--ar-*` variables) only reach elements that use the variables.
- **Touch targets.** The global rule `button, a, input, select, textarea { min-height: 48px }` also stretches inline text links and checkboxes. ARCHITECTURE §3.7 asks for 48 dp touch targets on controls, not on every inline element.

## Proposed change
- Set `body { background: var(--ar-bg); color: var(--ar-text); }` and drop `color-scheme: light` from `:root`, because `theme.css` sets `color-scheme` for each theme.
- Replace the global `min-height` rule with a `min-h-touch` utility (`@utility min-h-touch { min-height: var(--spacing-touch-target); }`), or limit the rule to `button` and form controls other than checkboxes and radios.

## Workaround in place
`theme.css` sets `background` and `color` on the shell root containers, and the components apply the 48 px minimum explicitly.

## Impact if rejected
Brief light flashes in dark mode, and taller-than-needed inline links.
