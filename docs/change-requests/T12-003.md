# T12-003 · Add schemaUpdate context to VALIDATION_FAILED for old payloads

Status: OPEN
Requested by: T12 · Wave: W5
Target: `packages/core/src/sync/push.ts` (owner: T02)
Kind: contract

## Problem
EC-SYN-09 says a payload written by an older app version is refused with `VALIDATION_FAILED` and that the client tells the user to update the app. The server answers `VALIDATION_FAILED` with only the Zod issues, so the client cannot tell an outdated schema apart from a genuinely invalid payload.

## Proposed change
When the payload fails validation and the device's `x-app-version` is below the minimum version for that mutation's schema, add `context: { schemaUpdate: true, minAppVersion }` to the per-mutation result.

## Workaround in place
The client keeps the refused command for review and never applies it. The chaos test for EC-SYN-09 asserts this behaviour and does not depend on the extra context.

## Impact if rejected
The conflict message is the generic "check the data" text instead of "update the app".
