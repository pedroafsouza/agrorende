# T14-002 · Apply the "from COMPLETED on" guard to the core external-cost function

Status: APPLIED
Requested by: T14 · Wave: W6
Target: `packages/core/src/modules/workOrders/service.test.ts` (owner: T07); `packages/core/src/modules/workOrders/external.ts` (owner: T14 after this change)
Kind: other

## Problem

DELIVERY-PLAN §5 T14 says `PATCH /work-orders/:id/external-cost` works "from COMPLETED on" and bumps `syncVersion`. T14 added `setExternalCostFromCompleted` in `workOrders/external.ts`. It refuses OPEN to ON_HOLD jobs with `INVALID_TRANSITION` (409) and cancelled jobs with `WO_CANCELLED`, and the route uses it. The older permissive `setExternalCost` cannot get the guard yet. The frozen T07 test `packages/core/src/modules/workOrders/service.test.ts:346` calls it on a job that is not completed, and that test would fail.

## Proposed change

- In `service.test.ts` around line 346, complete the job before calling `setExternalCost`, or call it on a seeded COMPLETED job.
- T14 (or T10) then makes `setExternalCost` delegate to `setExternalCostFromCompleted` and removes the duplicate.

## Workaround in place

The route `apps/web/src/app/api/v1/work-orders/[id]/external-cost/route.ts` calls `setExternalCostFromCompleted`, so the HTTP API already enforces the rule. `apps/web/src/app/api/v1/stock-movements/route.test.ts` covers it: COMPLETED gives 200 and a `syncVersion` bump, OPEN gives 409 `INVALID_TRANSITION`, CANCELLED gives `WO_CANCELLED`, and FIELD gives 403.

## Impact if rejected

Two core entry points with different rules stay in place. Only code that calls `setExternalCost` directly can still set an external cost before completion.

## Resolution

Applied by the W6 gate. `setExternalCost` now rejects a cancelled job with `WO_CANCELLED` and any job that is not COMPLETED or VERIFIED with `INVALID_TRANSITION`; `setExternalCostFromCompleted` remains as an alias for the route. `workOrders/service.test.ts` asserts the guard before recording the cost on a completed job.
